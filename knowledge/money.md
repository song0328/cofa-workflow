# 금액·정산·환불·대사

돈 계산은 **단위·반올림 시점·부분 처리** 세 가지가 정해지지 않으면 숨은 검사에서 1원 차이로 틀린다.

## 담당자에게 물을 것 (하나씩)
- "금액은 원 단위 정수인가요, 소수점이 있나요?"
- "반올림은 언제 하나요? 줄마다인가요, 합계에서 한 번인가요?" / "반올림·올림·버림 중 무엇인가요?"
- "할인과 세금(부가세) 중 무엇을 먼저 적용하나요?"
- "부분 환불이 되나요? 환불 합계가 결제액을 넘으면?"
- "두 자료의 금액이 다르면 어느 쪽이 기준인가요?" (대사)
- "취소·정정된 건은 집계에서 빼나요, 음수로 넣나요?"

## 흔한 함정
| 함정 | 막는 법 |
|---|---|
| `0.1 + 0.2 !== 0.3` (부동소수) | **정수(원·전 단위)**로 계산, 출력할 때만 형식화. Python은 `Decimal` |
| 반올림을 줄마다 vs 합계에서 → 결과 다름 | 담당자에게 먼저 묻고, "기준 없음"이면 가정 + A/B |
| JS `Math.round(-2.5) = -2` (음수 반올림) | 규칙을 함수로: `roundHalfUp` 직접 구현 |
| 통화·천 단위 구분자 섞인 문자열 `"1,200원"` | 입력 정규화 함수 하나, 실패는 오류 |
| 환불이 결제액 초과, 같은 환불 두 번 | 누적 환불 합계 검사, 요청 ID 중복 거절 |
| 합계 검증 없음 | 줄 합 = 총액, 결제 = 입금 + 미수 같은 **항등식**을 테스트로 |
| 화면에 원가·마진 노출 | 응답 필드 제한 (`security.md`) |

## 구현 요령
```js
const toWon = s => { const t = String(s).replace(/[,\s원]/g, ''); if (!/^-?\d+$/.test(t)) throw Error('INVALID_AMOUNT'); return Number(t); };
const roundHalfUp = (x, unit = 1) => Math.sign(x) * Math.floor(Math.abs(x) / unit + 0.5) * unit; // 음수도 대칭
const vat = won => roundHalfUp(won * 10 / 100);   // 비율은 정수 연산 뒤 반올림 한 번
```
```python
from decimal import Decimal, ROUND_HALF_UP, ROUND_DOWN
Decimal("1234.5").quantize(Decimal("1"), rounding=ROUND_HALF_UP)   # 1235
```
- 대사(맞춰 보기): 키(주문번호 등)로 두 자료를 붙여 **세 묶음**으로 나눈다 — 양쪽 일치 / 금액 불일치 / 한쪽에만 있음. 각 묶음 건수·금액을 보고서에.
- 중복 정정: "같은 키의 최신 정정본만" 같은 규칙을 먼저 확정(`data-quality.md`).

## 검사 사례
- 0원, 1원, 최대값 / 음수 금액 → 오류?
- 반올림 경계: x.5, x.4999, 음수 x.5
- 부분 환불 2번 합계 = 결제액 ✓, 1원 초과 ✗
- 대사: 일치 1, 금액 차이 1, 한쪽만 1 → 세 묶음 건수 확인
- 합계 항등식이 모든 테스트에서 성립
