# 화면 기본 — 업무 화면이 "되는 것처럼 보이지만 틀린" 곳

## 담당자에게 물을 것 (하나씩)
- "목록이 비었을 때 어떤 문구를 보여 주나요?"
- "실패하면 사용자에게 오류 코드를 보여 주나요, 안내 문장을 보여 주나요?"
- "되돌릴 수 없는 동작(삭제·승인)은 한 번 더 확인하나요?"
- "화면에서 보이면 안 되는 정보가 있나요?"

## 체크리스트 (구현 후 ui_sim과 사람 눈으로)
| 항목 | 확인 |
|---|---|
| 처음 열었을 때 | 선택 칸·목록이 데이터로 채워짐, 콘솔 오류 없음 |
| 빈 상태 | 0건이면 빈 표 대신 안내 문구 |
| 오류 표시 | 실패 이유가 화면에 보임, 입력값은 지워지지 않음, 기존 목록은 그대로 |
| 성공 후 | 목록·합계·잔액이 즉시 갱신 |
| 같은 로직 | 화면과 검사(`test`)가 **같은 함수**를 부름(로직을 화면에 복사하지 않음) |
| 출력 | 사용자 입력은 `textContent`로 (HTML 삽입 금지) |
| 숫자·날짜 | 단위 표시(원·일), 천 단위 구분 |
| 버튼 | 처리 중 중복 클릭 방지(필요한 과제에서), 권한 없는 동작은 숨김 + 서버에서도 거절 |
| 접근성 기본 | `<label>`로 입력 연결, 버튼은 `<button>`, 결과 문구는 `role="status"` |

## 흔한 함정
- 화면용 로직과 채점용 로직이 따로 → 화면은 맞는데 검사는 틀림(또는 반대)
- 에디터 미리보기에서 빈 칸 → 코드 오류가 아닐 수 있음. Browser 미리보기(서버)로 확인
- `innerHTML`로 사용자 입력 출력
- 새로고침하면 사라지는 저장 — 유지가 요구사항인지 확인(`localStorage`·서버 저장)

## 확인
```bash
node <키트>/tools/ui_sim.cjs index.html --list
node <키트>/tools/ui_sim.cjs index.html "set 칸=값" "click 버튼" "read 결과칸 목록칸"
```
ui_sim은 터미널 확인용(과제 파일에 넣지 않는다). 겉모양(가려짐·잘림·색)은 사람이 Browser로 1~3개.
