# 최적화·배정·경로·스케줄

핵심 불변식: **모든 항목은 정확히 한 번 배정된다(또는 미배정으로 명시된다)**, **hard 제약은 결과에서 한 건도 어기지 않는다.** 더 좋은 점수보다 이 둘이 먼저다. 진행 순서는 `playbooks/types/optimization.md`.

## 담당자에게 물을 것 (하나씩)
- "가장 줄이고 싶은 것 하나는 무엇인가요? 둘이 부딪히면 무엇이 먼저인가요?"
- "쓸 수 있는 자원(차량·인원·방) 수에 상한이 있나요?"
- "반드시 지켜야 하는 조건과, 어기면 감점 정도인 조건을 나눠 주실 수 있나요?"
- "모두 배정할 수 없으면 미배정으로 남기나요, 조건을 완화하나요? 누구부터 남기나요?"
- "거리·시간은 직선 거리인가요, 제공된 표인가요?"
- "결과가 매번 같아야 하나요? 동점이면 무엇을 먼저 고르나요?"
- "계산을 얼마나 기다릴 수 있나요(초·분)?"
- 기준선을 돌린 뒤: "후보 기준 ①②③ 중 무엇으로 할까요?"(숫자를 붙여서)

## 흔한 함정
| 함정 | 막는 법 |
|---|---|
| 제약 없는 최적화가 퇴화(그릇 하나에 한 명, 자원 무한) | 자원 상한·목적 순서를 담당자와 합의 |
| hard 제약을 조용히 벌점으로 바꿈 | hard는 검사기에서 위반 0. 못 지키면 "해 없음/미배정"으로 보고 |
| 큰 가중치(1000×a + b)를 임의로 정함 | 사전식 비교 `(미배정, 자원 수, 거리)` 튜플 |
| 그리디가 실패 = 해가 없다고 단정 | 그리디 실패는 "못 찾음"일 뿐. 하한·작은 입력 전수로 확인 |
| 실행 가능 = 최적이라고 씀 | 상태를 `feasible`(증명 없음)로 표시, 하한과 격차를 같이 |
| 생성기 함수로 검사(같은 버그를 같이 통과) | 검사기는 결과 파일만 읽고 규칙 정의로 다시 계산 |
| 실행마다 결과가 다름 | 동점은 id 순, 난수는 고정 seed, dict·set 순회 전에 정렬 |
| 지역탐색이 끝나지 않음 | 개선 폭 임계값(1e-9)·라운드 수·시간 상한 |
| n² 거리표가 10배 규모에서 메모리 초과 | n=1만이면 1억 칸. 가까운 후보 k개만 보거나 묶은 뒤 묶음 안에서만 계산 |
| 단위 혼동(분·초, km·m) | 입력 읽을 때 한 단위로 통일, 지표표에 단위 |

## 구현 요령
**문제 모양 → 쓸 만한 방법** (표준 라이브러리만으로 3시간 안에 현실적인 것)

| 문제 모양 | 먼저(기준선·그리디) | 다음(개선) |
|---|---|---|
| 배정(용량 있음) | 정렬 그리디, First-Fit-Decreasing | 교환·이동 지역탐색 |
| 거점 선택(몇 곳을 고름) | 그리디 커버(가장 많이 덮는 곳부터) | k-medoids 류 교체 |
| 묶기(군집) + 용량 | sweep(각도 순), 용량 차면 분할 | 경계 항목 이동 |
| 경로 순서(한 대) | 최근접 이웃 | 2-opt |
| 여러 차량 경로 | 묶은 뒤 묶음마다 경로 | savings(Clarke–Wright), 묶음 간 이동 |
| 시간창·근무조 | 시간대별로 나눠 각각 풀기 | 시간대 경계 항목 재배정 |
| 다목적 | 사전식 순서 | 1순위 고정 뒤 2순위 개선 |

- **pip이 안 될 수 있다.** OR-Tools·PuLP 같은 솔버를 가정하지 않는다. 설치돼 있으면 기준선을 만든 뒤에만 쓰고, 시간 상한과 결과 상태(`optimal`/`time_limit`)를 같이 받는다.
- **하한**을 먼저 계산해 격차를 보인다: 그릇 수 ≥ `ceil(총수요/용량)`, 돌아오는 경로 길이 ≥ 가장 먼 지점까지 왕복 거리 등. 하한과 같으면 그 지표는 최적이다.
- **복잡도**: FFD O(n·그릇), 2-opt 한 바퀴 O(n²), 전체 거리표 O(n²) 메모리. 10배면 거리표 100배다. 측정한 실행 시간과 함께 적는다.
- **결정성**: 정렬 키 끝에 id를 넣는다. `random.Random(seed)`를 함수 인자로 넘기고 전역 `random`을 쓰지 않는다.
- **비교 함수 하나**: 두 안의 우열은 `score(plan)`가 돌려주는 튜플 하나로만 비교한다. 화면·API·보고서가 같은 함수를 쓴다.
- **기준선 보존**: `baseline()`과 `improve()`를 따로 두고, 같은 입력으로 둘 다 돌려 지표표를 만든다.
- 코드 틀: `recipes/opt_heuristics.py`(거리, 하한, FFD, sweep, 최근접 이웃, 2-opt, 독립 검사기). 복사해 과제 계약에 맞게 고친다.

```python
def score(plan):            # 작을수록 좋음, 사전식
    return (len(plan.unassigned), len(plan.groups), round(plan.total_distance, 6))
best = min(candidates, key=lambda p: (score(p), p.id))   # 동점은 id
```

## 검사 사례
- 모든 항목이 정확히 한 번 배정(누락·중복 0), 미배정은 목록으로 명시
- 어떤 묶음도 용량 초과 0, 시간창·근무 시간 위반 0
- 검사기가 결과 파일만으로 다시 센 합계(거리·인원·자원 수) = 보고한 합계
- 같은 입력 두 번 → 바이트 단위로 같은 출력
- 함정 입력: 용량을 1 넘기는 입력 → 다른 결과(분할·미배정·오류), 딱 맞는 입력 → 그대로 통과
- 항목 6~8개 입력에서 전수 탐색 최적값 ≤ 휴리스틱 값, 하한 ≤ 전수 최적값
- 개선안 지표 ≤ 기준선 지표(사전식), 위반 0
- 해가 없는 입력(총수요 > 자원 상한 × 용량) → `infeasible` 또는 미배정, 서버 오류 아님
- 시간 상한 도달 → `time_limit`과 그때까지의 최선안, 마지막 확정안 유지
