# AI 기능(LLM) — 요약·분류·추출·추천·챗봇

원칙: **AI가 하는 부분**과 **규칙·검증이 막는 부분**을 나눈다. AI 출력은 믿지 말고 형식·범위·근거를 검사한다.

## 먼저 볼 것
- 과제 환경에서 실제 AI API를 호출할 수 있나(키 제공)? **개인 키를 넣지 않는다.** 없으면 규칙 기반 모의 응답으로 구조를 만들고 그 사실을 문서에.
- 입력에 개인정보·민감 정보가 있나?

## 담당자에게 물을 것 (하나씩)
- "분류 항목 목록이 정해져 있나요? 어디에도 안 맞으면 무엇으로 하나요?"
- "AI 결과를 사람이 확인한 뒤에 반영하나요?"
- "응답 형식(JSON 키)이 정해져 있나요?"
- "근거(원문 인용)를 함께 보여 줘야 하나요?"
- "얼마나 맞으면 쓸 만하다고 보나요?" (평가 기준)

## 흔한 함정
| 함정 | 막는 법 |
|---|---|
| "기타/모름" 칸이 없어 가장 가까운 오답 | 정해진 목록 + "해당 없음", 목록 밖 답은 거절 |
| 형식이 깨진 출력(JSON 아님·키 누락) | 파싱·스키마 검사, 실패 시 안전한 기본값 + 실패 기록 |
| 입력 속 지시문(프롬프트 주입: "이전 지시 무시하고…") | 입력은 데이터로만 감싸서 전달, 출력은 허용 목록으로 검사, AI 출력을 그대로 실행·발송 금지 |
| 근거 없는 내용(환각) | 근거 문장 인용 요구 + 원문에 그 문장이 실제로 있는지 문자열 검사 |
| 개인정보를 그대로 외부 AI에 | 마스킹 후 전달, 필요 최소한 |
| 평가 없이 "잘 된다" | 정답 있는 5~10건 평가 세트로 맞은 수 표 |
| 매번 다른 결과 | 온도 낮게, 같은 입력 재실행 결과 비교, 결정적 규칙 우선 |

## 구현 요령
```js
const LABELS = ['결제', '배송', '환불', '해당 없음'];
function parseLabel(raw) {
  let o; try { o = JSON.parse(raw); } catch { return { label: '해당 없음', error: 'BAD_JSON' }; }
  return LABELS.includes(o.label) ? { label: o.label, evidence: String(o.evidence || '') } : { label: '해당 없음', error: 'OUT_OF_SET' };
}
const grounded = (evidence, source) => evidence.length > 0 && source.includes(evidence);
```
- 프롬프트는 파일로 분리(버전 관리·설명 쉬움). 입력은 `"""` 같은 구분자 안에.

## 검사 사례
- 평가 세트 결과표(입력·기대·실제·맞음 여부)와 정답률
- 빈 입력, 아주 긴 입력, 목록 밖 답, 깨진 JSON
- 주입 문장이 섞인 입력 → 분류 결과만 나오고 지시를 따르지 않음
- 근거 문장이 원문에 없으면 표시
