# ①-질문 담당자에게 묻기 (10~40분 · 기다리는 동안 다른 일 진행)

## 규칙 (전부 지킨다)
- **한 메시지 = 물음표 하나.** 경우를 나열해도 묶음이다. AI는 우선순위 목록을 내고 사람은 **맨 위 하나만** 보낸다.
- 받는 사람을 앞에 쓴다: `인사팀 정책 담당에게: "…?"`. 업무 규칙은 업무 담당자에게, 화면 사용법은 Helper에게.
- 근거를 붙인다: `"[파일]의 [열]에 [값]이 n건 있는데, ○○로 봐도 될까요, △△로 봐야 할까요?"`
- 파일에 답이 있는 것은 묻지 않는다. "할 일을 1·2·3으로 알려 달라"는 금지.
- 순서: 지금 방식·불편 → 넘으면 안 되는 한계(숫자) → 이용자가 포기하는 선 → 무엇이 먼저인가 → 예외 대상 → 사용 빈도 → 역할·볼 수 있는 것 → 동시 수정·실패 시.
- 입력은 1000자 제한: 긴 답은 핵심 1~3문장으로, 그래도 길면 `답(1/2)`·`답(2/2)`로 나눠 받는다(다 오기 전엔 "받음"만).
- 답을 받으면 **파생 점검**(경계·다른 항목·제외 건의 분모·적용 순서·예외·과거 데이터 — `playbooks/stakeholder.md` "파생 점검")에서 결과가 바뀌는 것만 다음 질문 후보로.
- 답이 오면 **즉시** AGENTS.md 「2-1. 받은 자료」에 원문·출처·시각. "기준 없음"이면 「3. 가정」에 `기준 없음(시각)`, 다시 묻지 않는다. 출력 값·채우는 시점처럼 모든 결과에 찍히는 것이면 A/B 전에 `playbooks/decision-gates.md` "가정 고르기"(README 간접 단서, 초안 값은 근거 아님).
- 모호하게 물으면 "어떤 항목의 어떤 경우요?"만 돌아온다 → 열·값·행 ID·경계를 지목한다.
- "정해지지 않았다, 제안해 달라"면 **제안 1회**: "○○로 하려는데 그 안으로 진행해도 될까요?" → 승인이면 확정 사양(담당자 승인), 아니면 가정. 제안이 숨은 규칙과 부딪히면 담당자가 그 규칙을 알려 준다.
- 돌려 말하면: 쪼개기 → 선택지 2개 → 실제 샘플 행 하나 → 내 가정 확인(한 주제 최대 3번).
- 기다리는 동안: 뼈대·진단·검사 실행처럼 업무 기준과 무관한 것만. 기본은 메인 탭 하나로 진행한다.
