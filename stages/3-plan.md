# ② 사양·계획 (25~45분) — 사람이 계획을 확인하기 전에는 코드 수정 없음

## 할 일
1. AGENTS.md 「2. 확정 사양」(출처 표시)과 「3. 가정」을 나눠 채운다. 맨 위 진행 줄 갱신.
2. 핵심 담당자에게 **이해 확인 한 문장**: `"제가 이해한 목표는 ○○이고, 완료 기준은 ○○입니다. 이대로 진행해도 될까요?"`
3. **쉬운 말 표 2개**를 먼저 만든다: ① `파일·함수 / 입력 / 하는 일 / 출력 / 저장 위치·바꾸는 주체` ② 실제 역할별 `누가 누름·말함 → 검증·계산 파일 → 바뀐 상태 → 다음에 누가 봄`. 담당자가 규칙만 주면 `답변 → 규칙 → 검사`로 쓴다. 기존 앱·README를 보고 필요한 파일만 고치며, 표는 README 요구 문서(없으면 짧은 `DECISIONS.md`)에 둔다.
4. 필수부터 3~6단계 계획, 단계마다 "무엇으로 확인하나". **약 90분에 첫 완주**(필수 흐름이 끝까지 한 번 돎)가 되게.
5. 더 단순한 대안도 내고 **사람이 이유와 함께 고른다**. 사람이 AI를 재검토시켰다면 `첫 제안 → 내 의심·주장 → 재비교 근거 → 최종 선택 → 바뀐 코드·검사`를 실제 대화대로 남긴다. 결과를 바꾼 판단 1~3개만 기록한다. 읽기 전용 검증 탭은 계약 확정 뒤 꼭 필요할 때만 쓴다(`playbooks/parallel.md`).

## 계산·최적화가 있으면 (반드시)
- `python3 <키트>/tools/kit_read.py playbooks/types/optimization.md "모델 계약" "방법 수준" "담당자 2차 왕복"`
- 모델 계약(목적·반드시 지킬 조건·점수 조건·우선순위·지표·하한)을 README 요구 문서(없으면 `DECISIONS.md`)에 적는다.
- 방법 수준 A 단순 / B 그리디+개선 / C 정확해를 사람이 고른다.
- **2차 왕복**: 기준선 숫자를 붙인 2~3안을 담당자에게 보내 고르게 한다(10분 상한). 못 고르면 보수안 + 가정.
