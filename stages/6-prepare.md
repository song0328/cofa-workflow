# ⑥ 서술형 대비 (검사·문서를 마친 뒤 · 약 15분)

확인 문제는 **제출물과 작업 기록에서** 사람마다 다르게 나온다. 약 6문항 × 5분, 코드를 보지 않고 기억으로 답한다.

## 할 일
1. **5분 무힌트 회상(모의 문제보다 먼저)**: 사람은 코드와 노트를 보지 않고 아래 네 문장을 먼저 쓴다. AI는 새 답을 대신 쓰지 않고 제출물과 대조해 틀린 사실만 고친다.
   1) 무엇을 만들었고 데이터가 어떻게 흐르나
   2) 가장 중요한 결정 하나와 이유, 버린 대안
   3) 직접 확인한 숫자와 방법
   4) 가장 큰 한계와 운영한다면 먼저 할 일
2. 노트 「외울 것」은 회상에서 틀린 사실만 반영해 최종 정리한다.
3. **모의 확인 문제** (사용자가 `모의 확인 문제 해줘`, 아니면 AI가 권한다):
   - `python3 <키트>/tools/predict_questions.py .` → 예상 6칸(방법·구조·구현 vs 가정·장애·변화·AI 협업)에서 한 문항씩. **구조 칸은 역할 하나의 실제 데이터 흐름**, **AI 칸은 사람이 재검토시킨 실제 사례**를 반드시 묻고, 1개는 전제를 틀리게 한다. 「출제 범위 경고」가 있으면 그 파일을 빼거나 설명할 수 있게 한다.
   - **한 번에 하나씩.** 사람은 1~3문장(코드를 보지 않고). AI는 코드와 대조해 0~3점과 표시만: `근거 없는 숫자` · `없는 기능` · `과장` · `막다른 답`(모름으로 끝남) · `장황`(첫 문장에 답 없음) · `증거 없음` · 빠진 단계(결정→약점→파급→다음 검증).
   - 구조 답에는 파일·함수, 상태 저장 위치, 바꾸는 역할과 다음에 보는 역할이 있어야 한다. AI 판단 답에는 첫 제안, 내 이의·주장, 바뀐 결정, 확인 증거가 있어야 한다. 빠지면 쉬운 말로 사실 지도를 한 번 보여 준 뒤 코드 없이 다시 묻는다.
   - 약했던 칸은 **조건을 바꿔 한 번 더**(입력·역할·제약·실패 시점을 바꾼 새 질문). "알겠다"만으로는 통과가 아니다.
   - 틀린 사실은 노트 「말하면 안 되는 미확인 주장」에, 문서가 코드와 어긋나면 문서를 고친다. 시간이 없으면 3문항(전제 틀린 1개 포함).
(계약이 확정된 뒤 꼭 필요하면 읽기 전용 검증 탭으로 문서-코드 불일치만 점검할 수 있다 — `playbooks/parallel.md`)
4. `노트 보여 줘` → 파일 원문 그대로(`cat`). 사람이 두 번 읽는다.

## 답 틀 (사람에게 한 번 보여 준다)
`python3 <키트>/tools/kit_read.py playbooks/answer-cards.md "모든 답의 뼈대" "5분 쓰는 법" "하지 않는 것"`

사람이 원하면 바로 연습할 말: `역할별 데이터 흐름을 쉬운 말로 연습하자` · `내가 AI를 재검토시킨 사례만 질문해 줘`.
