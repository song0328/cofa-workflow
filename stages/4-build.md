# ③ 구현 (45~150분) — 한 단계씩, 검사로 닫는다

## 단계 하나의 순서 (매 단계 반복)
1. 지시받은 **한 단계만**. 빈 폴더면 `recipes/` 틀을 과제 계약에 맞게 고쳐 쓴다(과제 파일이 키트 경로를 참조하지 않는다).
2. 검사 실행 → 출력·종료 코드로 증명. "통과"는 **제공 검사 / AI가 만든 검사**를 나눠 말하고, 기대값의 출처(README 줄·담당자 답)가 붙은 사례 하나를 보인다.
3. 예외 하나 = 테스트 하나, 이름에 내용(`test_capacity_never_exceeded`).
4. **과제 파일만** 커밋(`git add <파일>`, `git add .` 금지), 메시지에 R번호.
5. AI 제안을 사람이 받아들이거나 고치거나 버리게 했으면 **그 자리에서** `AI_COLLABORATION.md` 「2」에 한 행(계기·판단·증거).
6. **이해 체크포인트**: "방금 만든 것 3줄(파일 이름 포함) + 확인 질문 1개". 사람이 `넘어가`면 넘어간다.
7. 확인문제 노트의 해당 카드와 「외울 것」만 고친다(카드마다 3줄, 70줄 이하, 실제 일만) → `노트 갱신: 카드 n`.
8. 사람에게 화면에서 넣어 볼 정상·경계·오류 입력 3개(「누를 것 → 보일 것」 한 줄씩).

## 조건이 맞으면 더 읽기
| 조건 | 읽을 것 |
|---|---|
| 최적화 단계 | `playbooks/types/optimization.md` "순서" · "검증"(기준선 보존, 독립 검사기, 같은 지표 표) + `recipes/opt_heuristics.py` |
| 화면 확인 | `playbooks/verification.md` "ui_sim 짧은 요청 처리" · 지도는 "지도·그림 화면" |
| 서버·미리보기 | `playbooks/flow.md` "화면 미리보기" |
| 막힘·같은 오류 3번 | `playbooks/recover.md` (원인 후보 2~3개부터) |
| 끊김·재접속·큰 일 맡기기 | `playbooks/codex.md` "끊김" · "큰 일 맡기기" |
| 돌발(담당자 답 변경·설치 실패 등) | `playbooks/situations.md` |

## 시간 점검
- 약 90분: 첫 완주 확인. 안 됐으면 범위를 줄인다.
- 약 120분: 남은 필수 n개, 선택조건을 버릴지 A/B.
- 약 150분(또는 제출 시작 −40분): **기능 동결** → `stages/5-check-report.md`

## 놓치면 안 되는 것

- [ ] 필수가 끝나기 전 선택조건 시작 X
