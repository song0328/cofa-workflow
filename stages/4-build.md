# ③ 구현 (45~150분) — 한 단계씩, 검사로 닫는다

## 단계 하나의 순서 (매 단계 반복)
1. 지시받은 **한 단계만** 한다. 빈 폴더면 `recipes/` 틀을 계약에 맞게 고친다(과제 파일이 키트를 참조하지 않음).
2. 핵심 검사 전 사람의 `예상: …` 한 줄 → 실행 뒤 `예상/실제/차이`를 노트에.
3. **제공 검사 / AI 검사**를 구분하고 출처 붙은 기대값 하나. 새 테스트는 올바른 이유로 실패하는 것을 먼저 본다. 통과시키려고 약화하지 않는다(`playbooks/verification.md` "테스트 정직성"). 0개 = 미검증.
4. 예외 하나 = 이름 있는 테스트 하나. 지름길에는 `# 한계: 무엇, 언제 바꿀지`.
5. 의미 있는 단계에서만 **과제 파일을 2~4회** 커밋한다. 위험한 변경 직전과 제출 직전은 반드시 남긴다(`git add <파일>`, 메시지에 R번호).
6. AI 제안이 결과를 바꿨으면 README 요구 문서에 남긴다. 재검토 사례는 `사람이 실제로 한 주장 / AI 재비교 / 바뀐 파일·검사`로 구분하고 이유를 꾸미지 않는다.
7. 이해 질문 1개: 실제 동작을 `역할 → 입력 → 파일·함수 → 검증·계산 → 저장 상태·소유자 → 다음 역할`로 묻고 틀린 사실만 고친다. 노트 갱신 → `노트 갱신: 카드 n`.
8. 사람 확인은 **번호로**: `S2-1 누를 것 → 보일 것`(정상·경계·오류). 사람은 `S2-1 실패: …`로 답한다.
