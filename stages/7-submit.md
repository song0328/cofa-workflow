# ⑦ 제출 (과제 타이머 15분 남으면 시작 · 실제 화면 안내가 우선)

## 순서
1. **제출물 정리**: AGENTS.md 「8. 제출물 목록」과 실제 파일 대조. 실험·임시 파일·worktree·키트 흔적을 찾는다. `pwd`, `git status -s`, `ls -a`. 과제 파일에 키트 참조가 없는지 `grep -rn "kit" --include=*.py --include=*.js --include=*.cjs .`
2. **로컬 키트 판정**: `/tmp/kit`이면 제출 폴더 밖이므로 그대로 둔다. `./kit`이면 README 요구 제출물이 모두 제출 루트에 있고 `./kit` 안에는 없는지 확인한 뒤, Codex는 지우지 말고 사람에게 판정과 명령을 준다.
   - `/tmp/kit`이 없고 노트를 남길 때: `확인 완료: ./kit 안에 제출물은 없습니다. 현재 제출 루트에서 mv -- ./kit /tmp/kit 을 입력하세요.`
   - `/tmp/kit`이 이미 있고 `./kit`이 중복 복제본일 때: `확인 완료: ./kit 안에 제출물은 없습니다. 현재 제출 루트에서 rm -rf -- ./kit 을 입력해도 됩니다.`
   - 경로·내용이 불명확하면 **삭제 가능하다고 말하지 않는다.** 사람이 명령을 실행한 뒤 `git status -s`와 제출 미리보기로 키트가 빠졌는지 다시 확인한다.
3. **깨끗한 상태로 다시 띄우기**: 새 데이터 폴더(`DATA_DIR=/tmp/fresh`)로 처음부터 실행해 `/health`와 핵심 흐름 하나(README가 Docker를 요구하면 `docker compose up --build`).
4. 과제가 정한 검사 명령(README·package.json·처음 받은 test 파일)을 찾아 **사람이 터미널에서 직접** 실행하게 한 줄로 준다. 실패면 제출하지 않고 그 오류만 고친다.
5. 사람: Ctrl+S 저장 확인 → 제출 문서 직접 읽기 → 위험한 변경이 없음을 확인하고 **제출 직전 커밋** → `노트 보여 줘` 두 번.
6. `제출하고 문제풀기` → 미리보기(일부만 보이고 숨김 폴더는 빠질 수 있다) → `제출물 확정하고 문제풀기` → 질문 생성 대기 5~10분 동안 「외울 것」 떠올리기.
7. **제출 버튼은 사람이 누른다.** 확인 문제가 시작되면 AI·키트는 쓰지 않는다.

## 사용자에게 건넬 말
