# ④ 대조 · ⑤ 제출 문서 (기능 동결 뒤 약 15분)

## 대조
1. 요건표 R마다 근거(코드 위치·검사 이름·출력)를 대조. 빠진 필수는 그것만 고친다. **담당자 확정 사항마다 검사가 있나**(「2-1」 → 테스트 이름) — 없으면 빈틈으로 보고.
2. 전체 검사를 다시 돌려 출력을 보인다(실행하지 않은 검사·사람이 보지 않은 화면을 확인했다고 쓰지 않는다).

## 제출 문서 (확인 문제의 출제 원천)
- **README가 요구한 문서가 먼저다.** 결정 근거와 AI 협업 기록은 그 문서 안에 넣는다. README가 문서를 요구하지 않을 때만 짧은 `DECISIONS.md` 하나를 내고, `AI_COLLABORATION.md`는 따로 요구할 때만 낸다.
- 문장마다 출처. **사람이 설명할 수 없는 내용·코드와 어긋나는 내용은 빼거나 코드에 맞춘다.**
- 계산이 있으면 요구 문서의 기준선 vs 개선 표·하한·계산 시간·동점 규칙을 채운다.
- 실패·동시성은 요구 문서에서 **지금 동작 / 운영 전에 더할 것**을 나눈다.
- 다른 보고서를 요구하면 `templates/report.md`.

## 사람이 이끄는 말 (예시로 준다)
"다른 사람이 이어받는다고 치고 실행·검사 명령, 가정, 남은 위험을 README에 3줄씩."

## 서술형 재료 점검
`python3 <키트>/tools/predict_questions.py .` → 「재료 부족」·「출제 범위 경고」·**「과장 단정어」**(최적·모든·보장·검증됨 → "실행 가능, 하한 대비 n%"·"검사 작성·실행함"처럼 근거 있는 말로)를 지금 고친다. 누가 했는지 구분: AI 실행 / 사람이 직접 조작 / 사람이 결정.
