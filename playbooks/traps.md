# 3시간 과제에서 흔한 함정

분석할 때 이 눈으로 README와 자료를 본다. 찾은 함정은 담당자 질문으로 바꾼다.

| 함정 | 예 | 대응 |
|---|---|---|
| 파일끼리 충돌 | 초안 정책 vs 개정 공지, 메일 숫자 vs 표 숫자 | 어느 쪽이 유효한지 담당자에게(한 번). 담당자가 기준 없음이면 README가 최신 기준이라 가리킨 문서·시행일이 늦은 공지를 따른다. 채택하지 않은 쪽과 이유를 문서에 |
| 의견 vs 확정 | "팀 의견: 검토했으면 발행 가능" | 확정된 것만 따른다 |
| 예외 데이터 | 중복·정정·취소·철회 기록, 비활성·품절, 기간 밖 날짜 | 처리 규칙을 묻고, 제외 사유를 남긴다 |
| 단서 조항 | 본문 뒤의 "다만·단·그러나·제외·예외" 한 줄이 결과를 바꿈 | 조항마다 단서까지 읽고 요건표 근거에 적는다 |
| 경계값 | 정확히 10분, 1~20 범위의 끝, 0건 | "정확히 ○일 때 포함인가요?" |
| 오류 우선순위 | 여러 오류가 동시에 해당 | "확인 순서"를 묻는다 |
| 권한 밖 행동 | 실제 환불·발송·승인·결제 | 하지 않는다. "승인 요청"까지만 |
| 정보 노출 | 원가·개인정보·내부 값이 응답에 섞임 | 출력 필드를 계약대로만 |
| 선택조건 미끼 | 화려한 선택 기능 | 필수가 끝난 뒤에만 |
| 기준 없음 | 담당자가 "정할 기준이 없다" | 가정으로 적고 넘어간다 |
| 업무 도구(SaaS) 안의 실제 동작 | 승인·발송·결제·삭제 버튼 | 누르지 않는다. 필요하면 담당자에게 "제가 직접 처리해도 되나요?"를 한 문장으로 확인 |
| AI 초안의 오류 | 제공 파일 속 "다른 AI가 쓴 초안" | 근거와 대조해 틀린 곳을 찾는다. 그대로 믿지 않는다 |
