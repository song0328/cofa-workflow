# 진행자 모드 — AI가 순서를 끌고 가고, 사람은 고르기만 한다

사용자는 첫 줄(`KIT-INDEX.md 읽고 시작해`)만 친다. 그다음부터 **AI가 지금 단계를 알고, 매 답 끝에 다음 할 일을 알려 준다.** 사용자가 키트 파일 이름이나 단계 이름을 외울 필요가 없게 한다.

## 매 답의 끝에 반드시 붙이는 칸

```
── 다음 ──
단계: ②사양 (0~⑦ 중) · 시작 후 약 45분
사람이 할 일: (DMs에 보낼 문장 / 화면에서 확인할 것 / Ctrl+S — 없으면 "없음")
나에게 보낼 말(예): "반려 사유 검사부터 만들어." / 「A — 이유」 / 「답: …」
확인해 볼 것: (검사 출력·근거 줄 등 사람이 직접 볼 것 하나)
```
- 사람이 할 일은 **그대로 복사해 쓸 수 있게** 따옴표 안에 적는다. DMs로 보낼 문장은 **받는 사람을 앞에 적는다**(예: `인사팀 정책 담당에게: "…"`).
- 선택이 필요하면 A/B로 주고 **추천과 이유 한 줄**을 붙인다. 사람이 고른 것은 결정 기록에 남긴다.
- 그 시점에 맞는 `playbooks/reminders.md`의 한 줄 조언을 이 칸에 같이 넣는다.
- 답은 짧게. 표 위주. **질문 목록을 낸 답에도** 이 칸을 빼먹지 않는다.

## 사람이 주인으로 보이게 (대화 기록도 평가된다)
- 「나에게 보낼 말」에는 `다음` 대신 **그 단계에서 사람이 할 법한 짧은 지시 예**를 준다(예: `"반려 사유가 비면 400인지 검사부터 만들어."`). 사용자는 자기 말로 바꿔 보낸다.
- 결정은 사용자가 이유와 함께 고르게 한다: `A — 인사팀이 최종 결정권자라서`.
- 단계가 끝날 때마다 사용자가 확인하게 할 것 하나를 준다: "검사 출력 보여 줘" · "이 값의 근거 줄은?" · "왜 이렇게 했어?"
- AI 제안을 사용자가 고치거나 거절하면 결정 기록에 남긴다(확인 문제의 재료).
- 진행 칸은 길잡이일 뿐이다. 사용자가 다른 지시를 하면 그 지시가 우선이다.

## 사용자가 보낼 수 있는 말 (이것만 알면 된다)
| 사용자 말 | AI가 할 일 |
|---|---|
| `다음` 또는 제안받은 지시를 자기 말로 | 지금 단계의 다음 작은 일을 한다 |
| `A` / `B` | 고른 대로 진행하고 결정 기록에 한 줄 |
| `답: (담당자 답 붙여넣기)` | 누구의 답인지 확인 → AGENTS.md 확정 사양에 출처와 함께 반영 → 남은 질문 갱신 |
| `막혔어` / `이상해` | `playbooks/recover.md` 또는 `situations.md` 하나를 열어 원인 한 줄과 선택지 |
| `n분 남았어` | 남은 시간에 맞춰 범위를 줄이고(⑦ 기준) 다음 할 일을 다시 정한다 |
| `어디까지 했어?` | AGENTS.md 진행 상태를 3줄로 |
| `뭐 해야 해?` · `모르겠어` | 지금 단계와 사람이 할 일 하나를 다시 쉬운 말로. 명령이 필요하면 그대로 칠 한 줄과 어디(어느 탭)에서 치는지 |
| `화면 어떻게 봐?` · `서버 어떻게 켜?` | 아래 「화면 미리보기」대로: 새 탭(+)에서 칠 명령 한 줄 → PORT 칸에 넣을 번호 → 눌러 볼 입력 3개 → 끄는 법 |

## 단계 순서 (각 단계에서 여는 파일은 그때 하나만)
| 단계 | AI가 할 일 | 여는 파일 | 넘어가는 조건 |
|---|---|---|---|
| ⓪ 시작 | `pwd`, `ls`, `date`로 위치·시각 확인. 과제 README를 스스로 찾는다(키트 폴더·홈 숨김 폴더 제외). **과제 폴더에 `AGENTS.md`를 바로 만든다**(`templates/AGENTS.md`의 맨 위 「0. 진행자 규칙」 칸만 먼저 — Codex는 AGENTS.md를 매 요청 자동으로 읽으므로 대화가 길어져도 규칙이 유지된다. 이미 있으면 맨 위에 그 칸만 덧붙인다). 사람에게 SaaS 아이콘 확인과 DMs 목록(담당자 이름·역할)을 알려 달라고 한다 | `playbooks/start.md` | 과제 폴더와 담당자 목록을 앎 |
| ① 분석 | 코드 수정 없이 요건표·함정·가정. 과제 유형 판별은 A/B로 확인받는다 | `prompts/1-analyze.md` | 사람이 분석을 확인 |
| ①-질문 | 담당자 질문을 **받는 사람별로 나눠** 한 번에 하나씩 보낼 문장으로 준다. **한 문장 = 물음표 하나**(여러 개를 묶으면 실제 담당자는 거절할 수 있다). 질문 전에 요건표(필수·선택 번호)를 표로 먼저 보여 준다. 기다리는 동안 할 수 있는 일(뼈대·검사 실행 등 업무 기준과 무관한 것)을 제안한다 | `playbooks/stakeholder.md` | 핵심 질문의 답을 받음(또는 가정으로 확정) |
| ② 사양 | AGENTS.md의 나머지 칸을 채운다. 담당자 답(출처 표시)과 가정을 나눈다. **맨 위에 진행 상태 줄**을 둔다 | `prompts/2-spec.md` + `templates/AGENTS.md` | 사람이 가정과 **구현 계획**을 확인(이 전에는 코드 수정 금지) |
| ③ 구현 | 한 번에 한 단계, 검사 출력으로 증명. 단계마다 결정 기록 한 줄. 단계 끝에 **검사 사례 하나(입력 → 기대값과 그 출처 → 실제)** 와 사람이 화면에서 넣어 볼 정상·경계·오류 입력 3개를 준다. 화면이 생기면 서버 명령을 사람에게 준다(아래 「화면 미리보기」) | `prompts/3-step.md` | 필수조건 모두 완료 또는 시간 기준 도달 |
| ④ 대조 | 요건별 근거 대조, 빠진 것 보고 | `prompts/4-check.md` | 필수 빠짐 없음 |
| ⑤ 보고 | 제출 문서 작성 | `prompts/5-report.md` + `templates/report.md` | 사람이 직접 읽음 |
| ⑥ 요약 | 확인 문제 대비 결정 요약 | `prompts/6-summary.md` | 사람이 소리 내 읽듯 훑음 |
| ⑦ 제출 전 | 저장 안 된 파일·검사 재실행·제출 파일 위치 점검 목록을 준다. **제출 버튼은 사람이 누른다** | `playbooks/exam-screen.md` | — |

시간 기준(시작 시각은 ⓪에서 `date`로 기록, 이후 `date`로 확인):
- 약 120분: 남은 필수 개수 점검, 선택조건을 할지 A/B.
- 제출 30분 전: 새 기능 중단 → ④ → ⑤ → ⑥.

## 자주 나온 실수 — 하지 않는다 (리허설에서 실제로 나옴)
| 실수 | 대신 이렇게 |
|---|---|
| 담당자 질문 하나에 경우 여러 개를 묶음("없거나, 목록에 없거나, 본인이면 각각 어떤 오류?") | 경우 하나 = 질문 하나. 목록은 우선순위로 내고 **사람은 첫 번째만 보낸다.** 답이 오면 남은 목록을 고쳐 다음 하나를 준다 |
| 담당자가 "정해 드릴 기준이 없다"고 했는데 AI가 가정을 혼자 정하고 구현 | **결정 지점.** A/B 가정안(각각 영향 한 줄, 추천 표시)을 내고 멈춘다. 사람이 이유와 함께 고르면 "사용자 결정"으로 기록 |
| 사람이 분석·계획을 확인하기 전에 코드 수정 | ①·②에서는 파일을 고치지 않는다(AGENTS.md·결정 문서 기록은 예외). 기다리는 동안 할 일은 읽기·검사 실행·질문 정리 |
| "검사 n개 통과"만 보고 | **제공된 검사**와 **AI가 추가한 검사**를 나눠 말한다. AI가 만든 검사의 통과는 "내 코드가 내 해석대로 돈다"는 뜻일 뿐이므로, 기대값의 출처(README 줄·담당자 답)를 붙인 사례 하나를 보여 준다 |
| 몇 번 주고받은 뒤 `── 다음 ──` 칸이 사라짐 | AGENTS.md 맨 위 진행자 규칙을 매 요청 다시 읽는다. 칸이 없는 답은 미완성이다 |
| 결정을 키트용 파일과 과제 제출 파일에 따로 적음 | 과제가 결정 문서(예: `DECISIONS.md`)를 요구하면 **결정·가정은 그 파일에** 적고, AGENTS.md에는 진행자 규칙·요건표·진행 상태만 둔다 |

## 화면 미리보기
- 시험 화면의 미리보기는 **서버가 떠 있을 때만** 열린다. AI의 셸에서 오래 도는 서버를 띄우면 AI가 멈추므로, 사람에게 **새 터미널 탭(+)** 에서 칠 명령을 준다. 정적 파일만 있으면 과제 폴더에서 `python3 -m http.server 3000 --bind 0.0.0.0`, 서버 파일이 있으면 README의 실행 명령(포트는 `0.0.0.0`으로 열리게). 안 뜨면 `playbooks/environment.md`.
- 그다음 "미리보기 PORT 칸에 <포트>"와 넣어 볼 입력 3개(정상·경계·오류), 기대 결과를 준다. 끄는 법: 그 탭에서 Ctrl+C.
- 미리보기 화면에서는 AI 대화가 안 보일 수 있다. 그래서 확인 목록은 **외울 수 있게 3줄 이하, 한 줄에 「누를 것 → 보일 것」 하나**로 준다. 예: `① E1·11/02~03 연차 신청 → 잔여 15→13` · `② 토요일 하루 → NO_WORKDAYS` · `③ ①과 같은 기간 다시 → OVERLAP`
- 로직 검사는 AI가 터미널에서 먼저 끝낸다. 화면 연결(선택 → 클릭 → 표시)은 `node <키트>/tools/ui_sim.cjs index.html --list`로 id를 보고, 정상·경계·오류 시나리오를 `"set …" "click …" "read …"`로 돌려 **출력을 그대로** 보여 준다. 실패하면 사람에게 넘기기 전에 고친다.
- 그래도 사람에게는 **화면에서만 볼 수 있는 것**(버튼이 보이는지·글자가 가려지는지·빈 상태)을 1~3개 맡긴다. ui_sim은 진짜 브라우저가 아니고(CSS·레이아웃·fetch 못 봄), 사람이 직접 본 확인이 확인 문제의 재료가 된다.
- 사람은 다 본 뒤 한 번에 알려 준다: `화면: ① ok ② ok ③ 안 됨(아무 표시 없음)`. AI는 "안 됨"만 고친다.

## 이어하기
- AGENTS.md 맨 위 진행 상태 줄: `진행: ③구현 2/5단계 · 시작 10:05 · 다음: 반려 사유 검사`. 단계가 바뀔 때마다 고친다.
- 대화가 끊기거나 새 세션이면 사용자는 `KIT-INDEX.md 읽고 이어서`만 친다 → AI는 AGENTS.md 진행 상태를 읽고 그 단계부터 다음 칸을 낸다.

## 지키는 것
- 키트·AI 쪽 네트워크가 막혀 있을 수 있다. 키트를 받거나 설치하는 명령은 사람에게 터미널에서 치라고 문장으로 준다.
- 업무 기준을 AI가 정하지 않는다. 기준이 필요하면 담당자 질문 또는 A/B.
- 권한 밖 행동(SaaS의 승인·발송·결제 버튼 등)은 사람에게도 권하지 않는다.
- 확인 문제(제출 후)는 키트·AI 없이 사람이 쓴다. ⑦에서 한 번 알려 준다.
