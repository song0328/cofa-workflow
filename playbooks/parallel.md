# 여러 탭 동시에 — 독립 작업·아이디어를 나눠 맡기기

Codex 탭 여러 개를 동시에 돌려도 된다. 단 **세션끼리는 대화를 공유하지 않는다.** 그래서 파일로 주고받고, 같은 파일을 둘이 고치지 않게 하고, 결과는 메인 탭 한 곳에서만 합친다.

## 역할
| 탭 | 하는 일 | 쓸 수 있는 것 |
|---|---|---|
| **메인(1번)** | 진행·사람과 대화·결정 기록·통합·검사·**커밋** | 전부. AGENTS.md·DECISIONS.md·AI_COLLABORATION.md·노트는 메인만 고친다 |
| 탐구 | 대안 설계 비교, 반론(약한 가정 찾기), 예외 사냥, 담당자 질문 초안, 예상 서술형 | **읽기 전용** + 결과 파일 하나 |
| 작업 | 계약이 정해진 독립 모듈 하나(예: 화면, 내보내기, 검사기) | **담당 파일만** |
| 검증 | 독립 검사기·테스트를 규칙에서 직접 만들고 실행 | 담당 테스트 파일만 |
- **동시에 많아야 3개(메인 포함 4).** 사람의 확인이 병목이고, 탭마다 토큰이 든다. 10/31 환경은 터미널 여러 개가 됐다는 후기가 있지만 메모리·연결이 불안정했다.
- 서버는 Codex 탭이 아닌 별도 터미널 탭에서 띄운다.

## 나누는 법 (메인이 한다 · 사람은 한 줄만 친다)
1. 메인이 작업 카드를 만든다(명령 1회):
   `python3 <키트>/tools/tab_task.py new T2 --role 탐구 --goal "…" --read README.md,DECISIONS.md --done "비교표와 추천"`
   작업 역할은 `--own 파일1,파일2`(담당 파일)가 필수이고, 진행 중인 카드와 담당 파일이 겹치면 거절된다.
2. 메인이 사람에게 준다: `새 터미널 탭(+) → codex → "/tmp/kit/work/T2.md 읽고 그대로 해."` (붙여넣기 없이 짧게 친다)
3. 보조 탭은 결과를 `/tmp/kit/work/T2-result.md`(20줄 이내)에 쓰고 멈춘다. 카드와 결과는 제출 폴더 밖이다.
4. 사람이 메인에 `T2 끝났어` → 메인이 결과를 읽고 **직접 검사를 돌려 확인한 뒤** 반영한다. 받아들이거나 고치거나 버린 것은 `AI_COLLABORATION.md`에 한 행(병렬 탐구는 좋은 서술형 재료다).
5. 반영했으면 `python3 <키트>/tools/tab_task.py done T2`. 상황판은 `status`.

## 언제 나누면 좋은가
| 시점 | 메인 | 보조 탭 예 |
|---|---|---|
| 담당자 답을 기다릴 때 | 질문 정리·사양 | 탐구: 예외 사냥(`playbooks/edge-hunt.md`), 자료 진단 결과 해석 |
| 계획 고를 때 | 사람과 결정 | 탐구 2개: **같은 문제를 서로 다른 방법으로 각각 설계** → 메인이 비교표로 사람에게 A/B |
| 계획 확정 전·첫 완주 뒤 | 진행 | 탐구: 반론 — "가장 약한 가정 3개와 깨지는 곳" |
| 구현 중 | 핵심 계산 | 작업: 화면·내보내기처럼 계약이 정해진 모듈 / 검증: 독립 검사기 |
| 제출 문서 쓸 때 | 문서 | 탐구: `tools/predict_questions.py` 결과로 예상 서술형과 문서·코드 불일치 찾기 |

## 탭 대신 Codex 내장 서브에이전트
탭을 늘리기 어렵거나 짧은 탐구·검증 하나를 맡길 때만 쓴다. 규칙은 탭과 같다.
- **먼저 도구가 실제로 있는지 확인한다.** 에이전트 생성 도구가 목록에 없으면 "서브에이전트 없음 → 순서대로 진행"이라 사람에게 말하고 메인이 차례로 한다. 역할극·가짜 로그로 흉내 내지 않는다.
- 모델·추론 수준은 **도구의 실제 인자로만** 정한다. 프롬프트에 "깊게 생각해"라고 쓰는 것은 설정이 아니다. 인자가 없으면 "지정 불가(기본값 사용)"라고 기록한다.
- 동시에 많아야 3개(메인 제외). 자식이 다시 위임하지 않게 지시에 적는다(중첩 금지).
- 자식은 읽기 전용이거나 담당 파일만 고친다. AGENTS.md·DECISIONS.md·AI_COLLABORATION.md 같은 공용 기록은 메인만 고친다 — 자식은 결과를 보고만 한다.
- 하나 끝나고 다음을 시작했다면 그것은 순차 실행이다. "병렬로 했다"고 기록·보고하지 않는다.
- 자식의 "완료·통과" 보고는 메인이 검사를 다시 돌려 확인한 뒤에만 반영한다.

## 하지 않는 것
- 계약(입출력·파일 경계)이 정해지기 전에 작업 탭을 나누지 않는다. 합칠 때 더 오래 걸린다.
- 두 탭이 같은 파일을 고치지 않는다. git 커밋은 메인만 한다.
- **worktree·복사본을 홈(제출 폴더)에 만들지 않는다**(10/31에 worktree 문서에서 질문이 나왔다). 실험은 `/tmp` 아래에서.
- 탭끼리 직접 대화시키지 않는다(확신만 커지고 틀린다). 결과 파일 → 메인 검증 → 사람 결정.
- 보조 탭의 "완료" 보고만 믿지 않는다. 메인이 검사를 다시 돌린다.
- 사람이 설명할 수 없을 만큼 많이 만들지 않는다 — 기능이 늘수록 서술형이 어려워진다.
