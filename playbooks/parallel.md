# 선택: 계약 확정 뒤 읽기 전용 검증 탭

**기본은 메인 탭 1개다.** 계약이 확정된 뒤 독립 검증이 꼭 필요하고 메인 탭만으로 하기 어려울 때만 이 절차를 선택한다. 여러 작업 탭을 동시에 열어 코드를 고치지 않는다. 세션끼리는 대화를 공유하지 않으므로 보조 탭은 읽기 전용으로 보고만 남긴다.

## 역할
| 탭 | 하는 일 | 쓸 수 있는 것 |
|---|---|---|
| **메인(1번)** | 진행·사람과 대화·결정 기록·통합·검사·**커밋** | 전부. AGENTS.md·DECISIONS.md·AI_COLLABORATION.md·노트는 메인만 고친다 |
| 검증(선택) | 계약·결과·문서의 불일치와 반례를 독립적으로 찾음 | **읽기 전용** + 결과 파일 하나 |
- 보조 탭은 하나만 쓴다. 서버는 Codex 탭이 아닌 별도 터미널 탭에서 띄운다.

## 나누는 법 (메인이 한다 · 사람은 한 줄만 친다)
1. 메인이 작업 카드를 만든다(명령 1회):
   `python3 <키트>/tools/tab_task.py new T2 --role 검증 --goal "불변식·문서 불일치 점검" --read README.md --done "반례와 근거"`
   역할은 `검증`, 목표는 읽기 전용 점검으로 적는다.
2. 메인이 사람에게 준다: `새 터미널 탭(+) → codex → "kit/work/T2.md 읽고 그대로 해."` (붙여넣기 없이 짧게 친다)
3. 보조 탭은 결과를 `kit/work/T2-result.md`(20줄 이내)에 쓰고 멈춘다. 카드와 결과는 키트와 함께 제출 전에 옮긴다.
4. 사람이 메인에 `T2 끝났어` → 메인이 결과를 읽고 **직접 검사를 돌려 확인한 뒤** 반영한다. 결과를 바꾼 판단은 README 요구 문서에 남긴다.
5. 반영했으면 `python3 <키트>/tools/tab_task.py done T2`. 상황판은 `status`.

## 언제 나누면 좋은가
| 시점 | 메인 | 보조 탭 예 |
|---|---|---|
| 계약 확정 뒤 핵심 계산 점검 | 구현·통합 | 검증: 불변식·경계값·독립 재계산 점검 |
| 제출 문서 대조 | 문서 | 검증: 제출 파일만 읽어 문서·코드 불일치 찾기 |

## 탭 대신 Codex 내장 서브에이전트
탭을 늘리기 어렵거나 짧은 탐구·검증 하나를 맡길 때만 쓴다. 규칙은 탭과 같다.
- **먼저 도구가 실제로 있는지 확인한다.** 에이전트 생성 도구가 목록에 없으면 "서브에이전트 없음 → 순서대로 진행"이라 사람에게 말하고 메인이 차례로 한다. 역할극·가짜 로그로 흉내 내지 않는다.
- 모델·추론 수준은 **도구의 실제 인자로만** 정한다. 프롬프트에 "깊게 생각해"라고 쓰는 것은 설정이 아니다. 인자가 없으면 "지정 불가(기본값 사용)"라고 기록한다.
- 동시에 많아야 3개(메인 제외). 자식이 다시 위임하지 않게 지시에 적는다(중첩 금지).
- 자식은 읽기 전용으로 결과만 보고한다. 공용 기록과 코드는 메인만 고친다.
- 하나 끝나고 다음을 시작했다면 그것은 순차 실행이다. "병렬로 했다"고 기록·보고하지 않는다.
- 자식의 "완료·통과" 보고는 메인이 검사를 다시 돌려 확인한 뒤에만 반영한다.

## 하지 않는 것
- 계약(입출력·파일 경계)이 정해지기 전에 작업 탭을 나누지 않는다. 합칠 때 더 오래 걸린다.
- 두 탭이 같은 파일을 고치지 않는다. git 커밋은 메인만 한다.
- **worktree·복사본을 홈(제출 폴더)에 만들지 않는다**(10/31에 worktree 문서에서 질문이 나왔다). 실험은 `/tmp` 아래에서.
- 탭끼리 직접 대화시키지 않는다(확신만 커지고 틀린다). 결과 파일 → 메인 검증 → 사람 결정.
- 보조 탭의 "완료" 보고만 믿지 않는다. 메인이 검사를 다시 돌린다.
- 사람이 설명할 수 없을 만큼 많이 만들지 않는다 — 기능이 늘수록 서술형이 어려워진다.
