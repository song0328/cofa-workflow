# 개발자처럼 이끌기 — 사람이 보낼 말과 생각할 순간

평가는 결과물만이 아니라 **AI를 이끈 방식**(대화 기록 전체)과 **자기 결과물 설명**을 본다. 사람이 키트에 의지하더라도, 대화 기록에는 **사람이 목표를 정하고, 근거를 요구하고, AI를 의심하고, 트레이드오프로 결정한 흔적**이 남아야 한다.

## AI가 지킬 것 (`── 다음 ──`의 「나에게 보낼 말」 예시를 만들 때)
- 예시 문장은 **개발자 지시 한 문장**: `무엇을 + 왜(요건·담당자 답·위험) + 어떻게 확인(검사·기대값)`. `다음`·`해 줘`만 있는 예시는 쓰지 않는다.
- 사람이 고를 일은 **선택지 2~3개 + 각 트레이드오프 한 줄 + 추천**으로 주고, 사람이 **이유를 붙여** 고르게 한다. AI가 대신 정하지 않는다.
- 사람이 자기 말로 바꿔 보내기 쉽게 짧게. 용어는 `playbooks/dev-glossary.md`의 말을 쓴다.
- 아래 「생각할 순간」이 오면 예시를 그 순간의 문장으로 준다.

## 생각할 순간 9가지 (예시 — 실제 과제 이름·값으로 바꿔서)
| 순간 | 사람이 보낼 말 예 | 개발자 사고 |
|---|---|---|
| 분석 직후 | "핵심 위험은 ○○로 보여. 자료에서 그 근거가 되는 행을 먼저 보여 줘." | 가설을 먼저 세우고 자료로 확인 |
| 질문 전 | "이 예외는 결과를 가장 크게 바꾸니까 이것부터 묻자. 근거 건수 붙여서 한 문장으로." | 영향 순서로 우선순위 |
| 계획 확정 전 | "구현 전에 모듈 표랑 데이터 흐름, 실패하면 어떻게 되는지부터 한 장으로 보여 줘." | 설계 먼저, 코드 나중 |
| 계획 반론 | "이 계획에서 가장 약한 가정 3개랑 그게 틀리면 깨지는 곳을 말해 줘. 고치지는 마." | 자기 설계를 반증해 봄 |
| 구현 지시 | "○○는 순수 함수로 분리하고, 불변식(○○ 위반 0) 테스트부터 써. 그다음 구현." | 계약·불변식·테스트 먼저 |
| 숫자 의심 | "이 ○○ 숫자 어디서 나왔어? 생성 코드 말고 결과 파일만 읽어서 다시 계산해 봐." | 독립 검증 |
| 반례 요청 | "이 로직이 틀리는 입력 3개 만들어서 돌려 봐. 경계값 포함." | 경계·반례로 깨 보기 |
| 범위 결정 | "남은 시간 ○분이면 ○○는 빼고 ○○를 확실히 하자. 뺀 이유는 DECISIONS에 적어." | 트레이드오프로 자르기 |
| 마무리 | "다른 사람이 이어받는다고 치고 실행·검사 명령, 가정, 남은 위험을 README에 3줄씩." | 인계 가능한 결과 |

## 사람이 하루 시험에서 꼭 남길 흔적 (최소 횟수)
- **AI를 의심하고 고친 기록 2회 이상** → `AI_COLLABORATION.md`(계기·판단·증거). 숫자 출처 요구, 반례 요청, 조용한 가정 발견 중 무엇이든.
- **선택지에서 이유를 붙여 고른 결정 3회 이상** → `DECISIONS.md`.
- **반론 요청 1~2회**: 계획 확정 전, 첫 완주 뒤. 같은 탭에서 "고치지 마"를 붙이거나 읽기 전용 두 번째 탭에서.
- **설명 확인 매 단계**: 이해 체크포인트에 한 줄로 답한다.

## 하지 않는 것
- 사람이 하지 않은 판단을 사람이 한 것처럼 기록하지 않는다(AI 제안이면 AI 제안으로).
- 일부러 틀린 지시를 하거나 연기하지 않는다. 실제로 확인하고 실제로 고른다 — 그래야 서술형에서 설명할 수 있다.
- 매 답마다 반론을 시키지 않는다(토큰). 위 순간에만.
