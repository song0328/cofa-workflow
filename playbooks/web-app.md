# 웹 화면·API 과제

## 만들 때
- README의 API 경로·필드·상태 코드·오류 형식을 **글자 그대로** 따른다. 필드를 더하지 않는다.
- 가능하면 제공된 스택·파일 구조를 유지한다. 새 프레임워크·라이브러리 설치는 꼭 필요할 때만(설치 실패·메모리 위험).
- 서버는 `0.0.0.0`으로 바인딩.

## 화면에서 직접 볼 것
- 정상 입력 → 기대 결과
- 경계 입력(빈 값, 최대 길이, 0, 정확히 기준값)
- 오류 입력 → 안내 문구가 나오고 **기존 데이터가 망가지지 않는지**
- 빈 상태(데이터 0건), 로딩, 실패 후 재시도
- 새로고침 뒤 유지돼야 하는 것이 유지되는지
- 작은 화면, 키보드만으로 조작(필요한 과제에서)

## API 확인 예
```bash
curl -s -i http://localhost:3000/items
curl -s -i -X POST -H 'Content-Type: application/json' -d '{"name":""}' http://localhost:3000/items   # 오류 경로
```
같은 요청 두 번(중복 처리), 없는 ID, 권한 없는 사용자도 README·담당자 답에 규칙이 있으면 확인한다.
