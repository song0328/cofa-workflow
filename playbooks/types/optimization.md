# 최적화·배정·경로·스케줄 과제

거점 선택·자원 배정·차량 경로·근무조 배치처럼 **조건을 지키며 더 좋은 안을 고르는** 과제. 규칙 몇 줄로 끝내면 "왜 알고리즘을 짜지 않았나"를 받는다. 지식은 `knowledge/optimization.md`, 코드 틀은 `recipes/opt_heuristics.py`.

## 먼저 볼 것 (처음 10분)
README·데이터로 채운다. 빈칸은 담당자 질문이 된다.

| 칸 | 채울 내용 | 예 |
|---|---|---|
| 결정할 것 | 무엇을 고르나·누구를 어디에 | 거점 몇 곳, 항목→그릇 배정, 방문 순서 |
| 반드시 지킬 조건(hard) | 어기면 결과가 무효 | 용량, 시간창, 1인 1배정 |
| 점수로 조정할 것(soft) | 어겨도 되지만 덜 좋음 | 선호, 균형, 대기 |
| 자원 상한 | 쓸 수 있는 개수·시간 | 차량 수, 최대 이동 시간 |
| 평가 지표 | 무엇이 작을수록·클수록 좋나 | 총거리, 미배정 수, 사용 자원 수 |
| 데이터 규모 | 행 수·지점 수·10배일 때 | n, n² 거리표 크기 |

## 모델 계약
`AGENTS.md`(과제가 결정 문서를 정했으면 그 파일)에 붙이고 출처를 단다. 답 없는 칸은 "미확인".
```
목적: <지표>를 최소화(최대화)한다          출처: README §x / 담당자 답
hard: <조건1>, <조건2> — 하나라도 어기면 결과 무효
soft: <조건3>(가중 또는 순위)
우선순위(사전식): 1) 미배정 수 2) 자원 수 3) 총거리
지표: 위 순서대로 표 한 장
하한: <예: ceil(총수요/용량)>
```
hard를 몰래 벌점(soft)으로 바꾸지 않는다. 여러 목적은 큰 가중치를 임의로 정하지 않고 사전식 순서로 둔다.

## 담당자 2차 왕복
제약 없이 최적화하면 "그릇 하나에 한 명"처럼 퇴화한다. **자원 상한·목적 순서를 합의**한다. 기준선을 돌린 뒤 **실제 숫자**를 붙여 후보 2~3개를 보낸다(아래 숫자는 형식 예시).
```
받는 사람에게: "기준을 하나 골라 주세요.
 ① 자원 수 최소(현재 18 → 하한 16, 대신 평균 이동 +12%)
 ② 총거리 최소(자원 18 유지, 거리 -9%)
 ③ 자원 상한 17 안에서 총거리 최소"
```
- 담당자가 고르면 계약의 목적·우선순위를 고친다.
- "기준 없음"이면 AI가 정하지 않는다. 보수적인 기본안(hard 전부 지키고 자원 수 우선 등) A/B를 사용자에게 내고, 고른 안을 "가정"으로 표시한다.

## 방법 수준 고르기
설계 선택이므로 **사용자가 이유와 함께 고른다**(`playbooks/decision-gates.md`). 결과를 `DECISIONS.md`에 적는다.

| 수준 | 방법 | 장점 | 위험 | 설명 난이도 | 예상 시간 |
|---|---|---|---|---|---|
| A | 정렬 그리디 | 빠름·설명 쉬움 | 개선 폭 작음 | 쉬움 | 20~40분 |
| B | 그리디 + 지역탐색(교환·이동·2-opt) | 개선 큼·표준 라이브러리로 가능 | 시간 상한·결정성 관리 | 보통 | 60~90분 |
| C | 정확해·솔버(설치돼 있을 때만) | 최적 증명 가능 | 설치·규모 한계, 시간 초과 | 어려움 | 불확실 |

추천은 보통 B. C는 기준선이 돈 뒤에만 시도한다.

## 순서
1. **기준선**: 가장 단순한 규칙으로 실행 가능한 결과. 지우지 않는다.
2. **독립 검사기**: 결과 파일만 읽고 규칙 정의로 제약을 다시 센다. 생성기 함수를 재사용하지 않는다.
3. **지표표**: 기준선 한 줄.
4. **개선 하나**: 방법 수준대로.
5. **비교**: 같은 입력·같은 지표표에 두 줄. 위반이 있으면 개선이 아니다.
6. **멈춤 규칙**: 개선 시도 두 번이 기준선을 못 이기면 멈추고 다듬기·검사·설명으로 넘어간다.

## 서비스로 연결
- 오래 걸리는 계산은 작업(job)으로: `queued → running → done / failed`, 작업 id로 조회.
- 결과 상태 표시: `infeasible`(해 없음 증명) / `feasible`(증명 없음) / `optimal` / `time_limit`.
- 입력이 바뀌면 이전 결과에 `stale` 표시. 늦게 온 옛 응답이 새 결과를 덮지 않게 작업 id·버전을 비교한다.
- 새 계산이 실패해도 **마지막 확정안**은 유지한다.

## 검증
- 검사기 위반 수 0, 보고한 합계와 검사기가 다시 센 합계 일치.
- 함정 입력: 제약을 어기는 입력과 지키는 입력의 결과가 달라야 한다. 같으면 제약이 적용되지 않은 것이다.
- 아주 작은 입력(항목 6~8개)은 전수 탐색 결과와 대조.
- 같은 입력 두 번 → 같은 출력(동점 순서·seed 고정).
- 실행 시간을 재고, 10배 규모에서 무엇이 먼저 터지는지 적는다.

## 확인 문제 재료
작업하면서 결정 문서와 확인문제 노트에 쌓는다.
- 목적함수 한 줄과 hard/soft 구분
- 고른 방법, 버린 대안과 이유
- 기준선 대비 수치표(같은 지표)
- 하한과 격차(예: 자원 16 하한, 결과 17 → 격차 1)
- 계산 시간, 데이터 10배일 때 바뀌는 점
- 동점 처리 순서와 seed — "같은 입력이면 같은 출력인가"에 답
