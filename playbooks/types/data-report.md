# 데이터 분석·정리·보고

**먼저 볼 것**: 파일 목록·행 수·열 이름, 기준일·버전, 질문(무엇을 결정하려는 분석인가), 제출 형식(보고서 md/csv/json/차트).

```bash
python3 <키트>/tools/csv_check.py data.csv --key id --number amount
python3 -c "import csv;r=list(csv.DictReader(open('data.csv',encoding='utf-8-sig')));print(len(r));print(r[0])"
```

**담당자에게 물을 숨은 규칙 예**
- 취소·중복·테스트 데이터는 빼나요?
- 비율의 분모는 무엇인가요?
- 기준 기간·기준일은?
- 두 자료의 숫자가 다르면 어느 쪽이 기준인가요?
- 보고를 받는 사람은 누구이고 무엇을 결정하나요? (맨 끝에 하나)

**흔한 함정**: 인코딩(BOM·CP949), 날짜 형식 혼재, 단위(원/천원), 결측을 0으로 처리, 중복 집계, 평균만 보고 분포 무시, 상관을 인과로 서술, 제공된 "AI 초안"의 숫자를 그대로 믿음.

**진행**: 정제 규칙표(무엇을 왜 뺐나, 몇 건) → 재현 가능한 스크립트 → 숫자 산출 → 보고서. 보고서의 모든 숫자는 스크립트 출력과 대조.

**결과물 모양**: 결론 3줄 → 근거 표(출처 파일·조건) → 제외한 것과 건수 → 한계·추가로 확인할 것. 권고와 확정 사실을 구분한다.
