# 사내 업무 시스템 (HR·결재·근태·예약·재고·정산 등)

핵심은 화면보다 **업무 규칙(상태·권한·계산)**이다. 규칙을 표로 먼저 확정하고, 규칙 하나 = 함수 하나 = 테스트 여러 개로 만든다.

**먼저 정리할 표**
| 무엇 | 예 |
|---|---|
| 역할·권한 | 신청자 / 팀장 / 인사팀 — 누가 무엇을 볼·바꿀 수 있나 |
| 상태 흐름 | 신청 → 승인/반려 → 취소 가능 여부 |
| 계산 규칙 | 연차 일수, 반차, 근무시간, 수당, 마감일, 반올림 |
| 날짜 규칙 | 주말·공휴일, 기간 겹침, 소급 신청 |
| 기록 | 누가 언제 무엇을 바꿨나(감사 기록) 필요 여부 |

**담당자에게 물을 숨은 규칙 예**
- "정확히 ○일/○시간일 때 포함인가요?" (경계)
- "본인 결재·자기 승인은 되나요?"
- "승인 뒤 취소하면 차감된 것을 되돌리나요?"
- "기간이 겹치는 신청은 거절인가요?"
- "규정과 팀 공지가 다르면 무엇이 기준인가요?"

**흔한 함정**: 권한 검사를 화면에서만 함, 상태를 건너뛰는 요청 허용, 날짜 경계(자정·말일·윤년), 개인정보를 목록에 다 노출, 실제 메일·결재 발송.

**검증**: 규칙표의 각 줄마다 정상·경계·거절 테스트, 다른 사람 자료 접근 거절, 상태 역행 거절.

**결과물 모양**: 규칙표(근거: README/담당자/가정), 상태도 한 줄, 권한표, 테스트 결과.
