# 예측·분류·모델 평가 과제

"불량·이탈·수요를 예측", "분류 정확도", "모델을 평가"가 결과물일 때 연다. 단순 집계로 요구가 끝나면 모델을 만들지 않는다(`playbooks/types/data-report.md`). README의 공식 분할·지표·제출 형식이 있으면 그대로 따른다.

## 먼저 볼 것 (예측 계약)
| 항목 | 정할 것 |
|---|---|
| 대상·라벨 | 한 행이 무엇(lot·wafer·고객·주문)이고 양성은 무엇인가 |
| 예측 시점 | 언제 예측하나 → 그때 알 수 있는 열만 특징 |
| 일반화 대상 | 새 개체인가, 미래 기간인가 → 분할 방식 |
| 오류 비용 | 놓침(FN)과 헛경보(FP) 중 무엇이 비싼가, 하루 확인 가능 건수 |
| 지표·제출 | 공식 지표, 예측 파일 형식 |

## 담당자에게 물을 것 (하나씩)
- "예측은 어느 시점에 하나요? ○○ 열은 그때 이미 알 수 있나요?"
- "놓친 불량 1건과 헛경보 1건 중 어느 쪽이 더 곤란한가요?"
- "하루에 몇 건까지 재검사(확인)할 수 있나요?" → 임계값 근거
- "새 lot에 쓰나요, 다음 달 자료에 쓰나요?" → 분할 근거
- "지금은 어떤 규칙으로 판단하나요?" → 기준선

## 누수 막기 (점수가 좋을수록 먼저 의심)
| 규칙 | 어기면 |
|---|---|
| 특징마다 "예측 시점에 아는 값인가"를 표로 확인. 사후 판정·재검사 결과·최종 bin·미래 구간 집계·라벨의 다른 이름은 뺀다 | 운영에서 못 쓰는 고득점 |
| 새 개체용이면 그룹(lot·wafer·고객 ID)으로, 미래용이면 시간으로 나눈다. 둘 다 필요하면 둘 다. 행 무작위 분할 금지 | 같은 lot이 양쪽 → 과대평가 |
| 결측 대체·스케일링·인코딩·특징 선택은 학습 부분에서만 맞추고 검증·테스트엔 적용만. 재표본화(오버샘플링)는 학습에만 | 평가 분포 왜곡 |
| 학습·평가 키 교집합과 중복 행을 센다 | 숨은 중복 |
| 정확도 99%·AUC 0.99처럼 의심스러우면 특징별 단독 점수부터 보고 누수 열을 찾는다 | 누수를 성과로 보고 |

```python
tr = {r["lot_id"] for r in train}; te = {r["lot_id"] for r in test}
assert not tr & te, "같은 lot이 양쪽에"                          # 새 개체용
assert max(r["ts"] for r in train) < min(r["ts"] for r in test)   # 미래용
```

## 기준선·지표·임계값
- 모델 전에 단순 기준선: 다수 클래스, 학습 평균·중앙값, 직전 값, 현재 업무 규칙. **같은 평가 행·같은 지표**로 비교하고 개선은 "기준선 대비 차이"로 말한다.
- 양성이 드물면 정확도만 쓰지 않는다: 혼동행렬(TP·FP·FN·TN), 정밀도·재현율, 경보 건수. 회귀는 MAE(단위 있는 오차) + 큰 오차 사례.
- 임계값은 **검증 구간에서** 업무 비용으로 고르고 고정한다. 최종 holdout은 마지막에 한 번만 보고, 거기서 다시 고르지 않는다. 이미 선택에 썼다면 "독립 테스트"라 부르지 않는다.
- 비용 기준이 없으면 확정하지 않는다: 후보 임계값 2~3개의 FN·FP 수를 표로 보여 담당자가 고르게 한다(`playbooks/stakeholder.md` "2차 왕복").
- 후보 모델은 시간에 맞춰 2~3개. 설치가 막히면 규칙·로지스틱 하나로 충분하다. 학습을 못 돌렸으면 성능은 "미실행".

## 보고
- 분할별 행 수·양성 수: "테스트 412행 · 양성 9". 양성 9건이면 재현율이 1건에 11%p씩 움직인다.
- 표본·양성·그룹이 적거나 기간이 짧으면 그렇게 쓴다. 계산하지 않은 신뢰구간·유의성은 쓰지 않는다(부트스트랩·여러 시점 분할로 범위를 냈을 때만 범위).
- 기준선보다 나빠도 그대로 보고한다. 특징 중요도·상관은 원인이 아니라 "원인 후보 + 추가 확인".
- 분할 근거·제외한 특징과 이유·실행 명령·seed를 `DECISIONS.md`에 한 줄씩.

## 확인 문제 재료
- "왜 그렇게 나눴나" → "새 lot에 쓸 모델이라 lot 단위로 나눴다. 행 무작위면 같은 lot의 비슷한 행이 양쪽에 들어가 점수가 부푼다."
- "임계값은 어떻게" → "놓침 비용이 크다는 담당자 답대로 검증 구간에서 재현율 우선으로 골랐고 테스트엔 그대로 썼다."
- "점수를 믿을 수 있나" → 특징 시점표·키 교집합 점검 결과 + 양성 수 + 기준선 차이.
- "운영하면 무엇이 달라지나" → 분포 변화(새 제품·설비), 라벨 지연, 주기적 재평가.
