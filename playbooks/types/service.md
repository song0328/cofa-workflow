# 새 서비스 (API·웹 화면)

**먼저 볼 것**: README의 엔드포인트·필드·상태 코드·오류 형식, 제공 스택(package.json 등), 실행·검사 명령, 데이터 저장 방식(메모리/파일/DB) 지정 여부.

**담당자에게 물을 숨은 규칙 예**
- 같은 요청 두 번 / 없는 ID / 빈 값일 때 결과
- 목록 정렬 순서·페이지 크기
- 상태가 바뀌는 조건과 되돌릴 수 있는지
- 여러 오류가 겹칠 때 먼저 알리는 것
- 저장이 서버 재시작 뒤에도 유지돼야 하는지

**흔한 함정**: 필드 추가, 지정 안 한 프레임워크 설치, 과한 인증·캐시·DB, 서버를 `localhost`로만 띄워 미리보기 안 됨, HTTP 200인데 화면 깨짐.

**구현 순서**: 데이터 모델 → 핵심 API 하나 → 검사 → 나머지 API → 화면(있으면) → 오류 경로.

**검증**: API마다 정상·경계·오류 `curl` 결과, 테스트 명령 출력, 화면에서 사람이 직접 3개 입력. 자세히 `playbooks/web-app.md`.

**결과물 모양**: 실행 방법 한 줄, API 표(요청→응답), 결정·가정, 미검증.
