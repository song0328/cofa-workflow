# 개발자 용어 30개 — 뜻 한 줄과 쓰는 문장

시험 전에 사람이 한 번 읽고, 지시·서술형에서 이 말로 말한다. AI도 설명할 때 이 말을 쓴다. 모르는 말을 아는 척 쓰지 않는다 — 실제로 한 일에만 붙인다.

## 요구사항·설계
| 용어 | 뜻 | 쓰는 문장 |
|---|---|---|
| 요구사항 추적 | 요건 번호(R1…)와 코드·테스트를 잇는 것 | "R3은 `test_reject_blank_reason`으로 확인했다." |
| 하드/소프트 제약 | 어기면 무효인 조건 / 덜 좋을 뿐인 조건 | "정원은 하드, 대기 시간은 소프트로 뒀다." |
| 목적함수 | 무엇을 줄이거나 늘릴지 한 줄 | "목적은 운행 수 최소, 동점이면 총 이동시간." |
| 책임 분리 | 입력·계산·저장·화면을 나눈 구조 | "계산은 DB를 모르는 순수 함수라 따로 테스트했다." |
| 순수 함수 | 같은 입력에 같은 출력, 바깥 상태를 안 바꿈 | "배정 계산을 순수 함수로 둬서 재현이 쉽다." |
| 데이터 계약(스키마) | 입력·출력 필드와 형식의 약속 | "API 응답 필드를 README 계약대로만 냈다." |
| 모놀리스 | 서버 하나에 기능을 모은 구조 | "3시간·소규모라 모놀리스로 했고, 계산이 무거워지면 작업 큐로 뗀다." |
| 과설계 | 요구보다 큰 구조 | "읽기 위주라 잠금은 넣지 않았다(과설계)." |
| 트레이드오프 | 하나를 얻고 하나를 잃는 선택 | "운행이 5% 줄었지만 평균 도보가 2분 늘었다." |

## 알고리즘·데이터
| 용어 | 뜻 | 쓰는 문장 |
|---|---|---|
| 기준선(baseline) | 가장 단순한 방법의 결과, 비교 기준 | "기준선 대비 같은 지표로 비교했다." |
| 휴리스틱 | 빠르지만 최적 보장은 없는 방법 | "그리디 + 2-opt 휴리스틱이라 전역 최적은 아니다." |
| 하한 | 이보다 좋을 수 없는 값 | "필요 대수 하한 16, 결과 17이라 격차 1." |
| 불변식 | 언제나 참이어야 하는 조건 | "모두 정확히 한 번 배정, 정원 초과 0을 불변식으로 검사했다." |
| 결정론 | 같은 입력이면 같은 결과 | "동점은 id 순으로 정해 결과가 매번 같다." |
| 시간 복잡도 | 데이터가 커질 때 계산량이 느는 정도 | "거리표가 n²이라 10배면 100배가 먼저 문제다." |
| 경계값 | 기준 바로 위·아래·같은 값 | "정확히 정원일 때와 1 초과일 때를 따로 테스트했다." |
| 정규화 | 표기를 하나로 맞춤 | "WORK/work를 대문자로 정규화했다(담당자 확인)." |

## 서비스·운영
| 용어 | 뜻 | 쓰는 문장 |
|---|---|---|
| 인증/인가 | 누구인가 확인 / 무엇을 할 수 있나 확인 | "인가는 서버에서 세션의 사용자 ID로 검사한다." |
| 소유권 검사 | 본인 데이터만 보게 서버가 막음 | "클라이언트가 보낸 ID는 믿지 않는다." |
| 트랜잭션 | 여러 변경을 전부 하거나 전부 안 함 | "저장 중 오류면 전부 롤백돼 이전 계획이 남는다." |
| 원자적 교체 | 다 만든 뒤 한 번에 바꿈 | "새 계획은 임시 파일에 쓰고 성공하면 교체한다." |
| 낙관적 잠금 | 버전 비교로 동시 수정 충돌 감지 | "버전이 다르면 409로 '다른 사람이 먼저 바꿨다'." |
| 멱등성 | 같은 요청이 두 번 와도 한 번만 반영 | "확정 버튼을 두 번 눌러도 계획은 하나다." |
| 비동기 작업(job) | 오래 걸리는 일을 따로 돌리고 상태로 조회 | "재계산은 작업 ID를 주고 상태를 조회하게 했다." |
| 헬스체크 | 서버가 살아 있는지 확인하는 주소 | "`/health`가 DB까지 확인한다." |
| 롤백 | 이전 상태로 되돌리기 | "확정본을 버전으로 남겨 되돌릴 수 있다." |
| 관측성(로그) | 무슨 일이 있었는지 남기는 것 | "누가·언제·무엇을 바꿨는지 변경 기록을 남긴다." |

## 검증·협업
| 용어 | 뜻 | 쓰는 문장 |
|---|---|---|
| 독립 검증 | 생성 코드와 다른 경로로 다시 계산 | "결과 파일만 읽는 검사기로 위반 수를 다시 셌다." |
| 회귀 테스트 | 고친 뒤 예전 기능이 안 깨졌는지 | "버그를 재현하는 테스트를 먼저 실패시키고 고쳤다." |
| 테스트를 테스트 | 검사를 지우면 테스트가 실패하는지 | "정원 검사를 빼 보니 테스트가 실패해 검사가 살아 있음을 확인했다." |
| 인계(handoff) | 남이 이어받을 수 있게 남기는 것 | "README에 실행·검사 명령과 가정을 적었다." |
