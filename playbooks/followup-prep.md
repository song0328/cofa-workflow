# 확인 문제 대비 — 작업하면서 미리 준비한다

제출 뒤 확인 문제는 **고정된 제출물을 바탕으로** 나오고, **본인의 작업을 설명하는 답변**이 평가된다. 줄 번호 암기보다 **내가 한 결정을 내 말로** 말할 수 있으면 된다. 확인 문제 중에는 키트·AI를 쓸 수 없으므로, **작업 중에** 준비한다.

## 나올 수 있는 질문 유형
| 유형 | 예 (모양만) | 답에 넣을 것 |
|---|---|---|
| 핵심 동작과 확인 방법 | "만든 것이 무엇을 하며, 어떻게 확인했나" | 핵심 기능 1~2개 → 정상·경계·오류 중 직접 해 본 입력과 결과 → 검사 명령 |
| AI 제안을 다룬 방식 | "AI 제안을 어떻게 확인·수정했나" | AI가 제안한 것 → 내가 확인한 방법 → 고치거나 거절한 것과 이유 |
| 목표와 완료 기준 | "무엇을 완료로 봤나" | 목표 한 문장 → 완료 기준(요건 번호) → 담당자 확인 / 내 가정 구분 |
| 결정의 이유 | "왜 이렇게 설계했나" | 선택 → 이유(담당자 답·README) → 버린 대안 |
| 변경 대응 | "규칙이 바뀌면 어디를 고치나" | 코드 위치 → 테스트 값 → 문서 |
| 한계 | "확인하지 못한 것은" | 못 본 것 → 위험 → 다음에 할 것 |

## 작업 중 AI에게 시킬 것
- 단계가 끝날 때마다: `방금 단계의 핵심 결정 한 줄과 확인 방법 한 줄만 AGENTS.md 맨 아래 "결정 기록"에 추가해.`
- 제출 30분 전: `prompts/6-summary.md 대로.` → 결과를 **사용자가 직접 소리 내 읽듯** 훑는다.
- AI 제안을 고치거나 거절했을 때마다 한 줄 기록(이게 두 번째 유형의 답 재료다).

## 답 쓰는 요령 (5분, 3~5문장)
1. 첫 문장에 결론 (무엇을 했다 / 무엇으로 확인했다)
2. 구체적인 입력값·결과를 하나 넣는다 ("빈 이름을 넣으면 400과 오류 문구")
3. 담당자 확인인지 내 가정인지 밝힌다
4. 못 한 것 하나를 솔직히 쓴다
5. 시간이 끝나면 자동 확정되므로 짧게라도 먼저 쓰고 다듬는다
