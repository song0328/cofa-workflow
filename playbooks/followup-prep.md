# 확인 문제 대비 — 작업하면서 미리 준비한다

## 알려진 형식 (공개 안내·10/31 응시자 후기 · 실제 화면이 우선)
- 제출을 확정하면 **질문 생성 대기 5~10분**이 있다(답변 시간 아님). 그다음 **약 6문항, 문항당 약 5분**이다.
- 문항마다 시간이 따로 흐르고 끝나면 자동 확정된다. 이전 문항으로 돌아갈 수 없고, 붙여넣기는 안 된다. 키트·AI도 쓸 수 없다.
- **질문은 AI가 내 제출물과 작업 기록을 읽고 사람마다 다르게 만든다.** 예: 검증용 스크립트, README가 요구한 사용 문서, 그 안의 결정·AI 협업 기록을 짚은 질문.
- **답할 때 코드를 볼 수 없다.** 코드 조각을 해석시키는 형식이 아니다. 내가 만든 것을 기억으로 설명한다.
- 10/31에 나온 주제: 알고리즘 선택 이유, 모듈 책임과 데이터 흐름, 운영자/사용자 격리와 권한, 장애·동시 수정 시 동작, 모놀리스·동기/비동기·운영 전 고려, AI 코드 검증, 트레이드오프. → 9가지 카드로 정리했다: `playbooks/answer-cards.md`
- 다른 Cofa 시험 후기에서 더 확인된 것:
  - **제출 폴더의 파일을 전부 읽고** 묻는다. 제출용이 아닌, AI가 쓴 협업 md가 폴더에 남아 있었는데 거기서도 문제가 나왔다.
  - **한 주제에 꽂힌다.** 작업 중 특이한 것 하나에 공을 많이 들인 사람은 6문항 중 4개가 그것만 물었고, 비슷한 질문이 2~3번 반복됐다. 반대로 말하면 **제출 문서에서 가장 눈에 띄는 주제가 질문을 끌어온다.**
  - 문항 예: "핵심 로직은 무엇을 했고 왜 그렇게 했나", "서비스 장애가 어디서 발생할 것 같나", 협업 문서에 적은 사례.
  - README가 어떤 문서를 **본인이 직접 쓰라**고 하면, AI는 사실 목록(언제·무엇·증거)만 주고 문장은 사람이 직접 친다.
- 공식 평가 축: **결과물 완성도 · AI를 이끈 방식 · 자기가 만든 것을 설명할 수 있는지**(기술·의도·인지). 서술형이 가장 큰 변별 요소였다는 후기가 많다.

## 예상 칸 6개 — 10/31 응시자 두 명의 문항을 겹치면 같은 구조였다
| 칸 | 응시자 A의 문항 | 응시자 B의 문항 | 답 카드 |
|---|---|---|---|
| 1 방법 선택 | 단순 방법 대신 택한 알고리즘의 근거·대안·한계 | 왜 (최적화) 알고리즘을 짜지 않았나 | 1 |
| 2 구조·데이터 흐름 | 데이터가 거치는 모듈, 상태 저장 위치·소유자 | 사용자 입력과 운영자·담당자 판단이 어디서 만나고 다음 역할에 보이는가 | 2·3·5 |
| 3 구현 vs 가정 | 구현·검증한 것과 가정의 구분, 평가자가 확인할 경로 | 실제로 구현한 것과 확인 방법 | 7 |
| 4 장애·운영 | (기록 없음) | 다른 운영자가 동시에 고치거나 오류가 나면 | 4·5 |
| 5 변화·판단 | 조건이 바뀌면 추가 검증, AI 결과 판단 근거 | 트레이드오프 | 8 |
| 6 AI 협업 사례 | AI 제안을 왜 다시 생각하게 했고 내 주장이 무엇을 바꿨나 | AI가 처리한 것을 무엇을 보고 수용·수정·폐기했나 | 6 |
- **10/31 관찰에서는 6칸 구조였지만 실제 화면이 우선**이다. `python3 <키트>/tools/predict_questions.py <과제 폴더>`로 제출 파일의 결정·협업 기록을 넣은 예상 질문과 전제가 틀린 질문 1개를 뽑는다.
- 칸 2(상태 소유)와 칸 4(장애)에는 **자료 오류의 책임 경계**도 들어간다: 누가 발견·수정·승인·복구하나. 칸을 늘리지 않고 카드 4의 답 틀(`오류 위치 → 책임 분리 → 보존·복구 → 한계`)로 답한다.
- 칸 1·6의 재료는 README가 요구한 문서 안의 결정 근거와 AI 협업 판단이다. 문서 요구가 없으면 짧은 `DECISIONS.md`에 함께 둔다.

## 핵심 전략 — 출제 범위를 내가 정한다
질문이 제출물에서 나오므로, **제출물을 내가 아는 것으로만** 채운다.
1. **제출 문서는 README가 정한다**: 요구한 문서 안에 결정 근거와 AI 협업 기록을 넣는다. 문서 요구가 없을 때만 짧은 `DECISIONS.md` 하나를 내며, `AI_COLLABORATION.md`는 따로 요구될 때만 낸다.
2. **AI가 따로 만든 잡문서·실험 파일·worktree·임시 스크립트를 제출물에 남기지 않는다**(남은 AI 협업 md에서도 실제로 출제됐다). 남길 검사 파일은 이름만 봐도 무엇을 확인하는지 알게 한다(`test_capacity_never_exceeded.py`).
3. **코드는 필요한 파일만** 고친다. 기존 앱 수정이면 1~2개일 수 있다. 역할과 데이터 흐름은 제출 문서에서 설명한다.
4. **제출 전에 사람이 제출 문서를 전부 직접 읽는다.** 읽지 않은 문서는 내지 않는다.
5. **가장 눈에 띄는 주제를 내가 고른다.** 제출 문서에서 가장 크게 다루는 결정은 내가 제일 잘 설명할 수 있는 것으로 한다. 설명하지 못하는 특이한 기능은 문서에서 키우지 않는다.

## Answers.md — 제출 폴더의 질문·답 (⑥에서 만든다)
사람이 확인 문제 전에 **이 파일 하나만 읽으면 되게** 만든다. 서술형에서는 내 말로 답하고 끝에 `(자세한 내용: Answers.md 3번)`을 붙인다.
- **위치**: 제출 루트 `Answers.md`. 틀은 `templates/Answers.md`(맨 위 `>` 안내 줄은 지운다). README가 제출 파일 목록을 제한하거나 추가 문서를 막으면 만들지 않고, 같은 내용을 README 요구 문서의 한 절에 넣는다.
- **재료**: 노트 「외울 것」·카드별 사례, `predict_questions.py` 출력, 모의 확인 문제에서 틀렸던 것. 노트는 AI 작업용(제출 안 함), `Answers.md`는 사람이 읽는 최종본이다.
- **모양**: `# Answers` → 「한눈에」 → 「핵심 결정 집중」 표 → `## 1. 질문`, `## 2. 질문` … 번호만 붙인다. "예상 질문" 같은 제목, `Q1`, `근거:` 줄은 쓰지 않는다.
- **예시**: `templates/Answers-example.md`(가상 회의실 배정)의 분량·말투·구성을 따른다. 그 문장·숫자는 쓰지 않는다.
- **쓰는 법**: 답은 쉬운 말로 4~8문장의 짧은 문단, 순서는 `결정·이유 → 약점 → 파급 → 다음 검증`. 개발 용어는 풀어 쓰고, 파일·함수 이름은 꼭 필요할 때 한두 개만. 숫자는 직접 확인한 것만 넣는다. 코드·검사 출력으로 확인한 사실만 쓰고, 노트 「말하면 안 되는 미확인 주장」은 넣지 않는다.
- **핵심 결정 집중 표**: 질문이 한 주제에 몰릴 때를 대비해, 핵심 결정 하나를 왜·대안·약점·확인·조건 변화·AI 역할의 6각도로 따로 답한다. 비슷한 질문이 또 나오면 같은 답을 되풀이하지 않고 다른 각도의 답을 쓴다.
- **검사**: 쓴 뒤 `python3 <키트>/tools/predict_questions.py .`의 「과장 단정어 경고」에 이 파일이 나오면 고친다. 코드와 어긋나면 코드에 맞춘다.
- **사람**: 전부 읽고, 내 말과 다른 문장은 고쳐 달라고 한다. 설명할 수 없는 줄은 지운다(출제 범위다). 그다음 `답 파일 보여 줘` → 원문 `cat`을 제출 전에 두 번 읽는다.

## 작업 중 이해 체크포인트 (③ 단계마다 · 30초)
- 단계가 끝날 때마다 AI가 **"방금 만든 것 3줄 설명(파일 이름 포함) + 확인 질문 1개"**를 낸다.
- 사용자는 한 줄로 답한다. 틀리면 AI가 맞는 사실을 한 줄로 짚는다. 대화 기록도 채점되므로, 사람이 이해한 흔적이 남는다.
- 확인 질문은 카드 축에서 하나 고른다. 구조 질문은 `역할 → 입력 → 실제 파일·함수 → 저장 상태·소유자 → 다음 역할`을 한 건으로 추적한다. 예: "운영자가 저장을 누르면 어떤 파일을 거쳐 무엇이 바뀌고 사용자는 어디서 보지?"
- 사람이 AI 제안을 재검토시켰으면 즉시 "첫 제안 / 내가 의심한 점·주장 / 최종 결정 / 바뀐 파일·검사"를 되묻고, 사람이 실제로 답한 내용만 카드 6에 남긴다.
- 사용자가 `넘어가`라고 하면 넘어간다. 강요하지 않는다.

## 확인문제 노트 — AI가 작업 중에 채운다
- **위치**: `<키트>/notes/확인문제-노트.md`(시험 중 `./kit/notes/…`, 제출 직전 키트와 함께 이동). 틀은 `templates/answer-notes.md`. 노트는 제출하지 않는다. 환경이 재시작돼 사라지면 키트를 다시 받고, 제출 문서·대화에서 확인되는 사실만 복구한다.
- **생성·복구**: 시작·이어하기·단계 전환 때 실제 파일이 있는지 본다(매 답마다 하지 않는다 — 토큰). 없으면 즉시 만든다. `DECISIONS.md`는 제출용 근거 기록이고 노트의 대체물이 아니다. 계획 승인·담당자 답·과거 검사를 새로 만들어 쓰지 않는다.
- **언제**: 단계가 끝날 때, 사용자가 A/B를 고르거나 AI 제안을 고치게 했을 때, 담당자 답이 규칙을 바꿨을 때, 기준선·개선 수치가 나왔을 때. 해당 카드 칸과 「외울 것」만 고친다.
- **얼마나**: 카드마다 최대 3줄, 파일 전체 70줄 이하. 덧붙이지 말고 바꿔 쓴다. **외울 문장만** 쓴다(노트 작업 자체·"미확인" 설명은 쓰지 않는다 — 미확인은 카드 7에만). 사례가 없는 카드는 비운다.
- **어떻게**: 실제 값과 출처 하나를 쓴다(`인사팀 20:52` · `내 가정` · `test 출력` · `README 7`). AI만 실행했으면 `(AI)`, 사람이 직접 봤으면 `(내가 봄)`. 사용자 확인이 기록돼 있을 때만 1인칭으로 쓴다.
- **사람 몫**: 「다시 한다면」·「시간 배분」은 사용자가 실제로 말했거나 `<키트>/notes/MY.md`에 쓴 것만 쓴다. MY.md의 `결정`·`의심` 줄은 사람이 직접 한 판단의 증거다 — 카드 6·9에 `(내가 봄)`으로 옮긴다. MY.md 자체는 사람 파일이라 고치지 않는다. 없으면 비우고, `노트 보여 줘` 끝에 "이 두 줄은 직접 생각해 두세요"라고만 덧붙인다.
- 파일을 쓰고 다시 읽어 존재·갱신·70줄 이하를 확인한 뒤에만 `노트 갱신: 카드 n`이라고 알린다. 쓰기에 실패하면 그 사실을 밝힌다.
- `노트 보여 줘`: 최신 상태를 확인·보완한 뒤 **파일 원문을 그대로 출력한다**(`cat`, 표·요약 금지 — 외울 문장이 원문이다).

## 무힌트 회상 뒤 모의 확인 문제 (⑥ · 사용자가 `모의 확인 문제 해줘`)
1. 먼저 5분 동안 사람은 코드·노트 없이 네 문장을 쓴다: ① 무엇을 만들었고 데이터가 어떻게 흐르나 ② 가장 중요한 결정 하나와 이유, 버린 대안 ③ 직접 확인한 숫자와 방법 ④ 가장 큰 한계와 운영한다면 먼저 할 일. AI는 제출물과 대조해 틀린 사실만 고친다.
2. 그다음 `python3 <키트>/tools/predict_questions.py <과제 폴더>`를 돌린다. 6칸에서 한 문항씩 고르되 **그중 하나는 전제를 일부러 살짝 틀리게** 낸다. 질문을 다듬을 때는 **제출할 파일만** 읽는다.
   - 2번 칸은 역할 하나의 입력부터 다음 역할의 화면까지, 6번 칸은 사람이 AI를 재검토시킨 실제 대화 하나를 반드시 고른다.
3. **한 번에 한 문항씩** 낸다. 사용자는 1~3문장으로 답한다(코드를 보지 않고).
4. AI는 답을 **코드·출력과 대조해** 0~3점과 표시만 준다: `근거 없는 숫자`·`없는 기능`·`과장`·`막다른 답`·`장황`·`증거 없음`·빠진 단계(결정→약점→파급→다음 검증). 모범 답안을 길게 쓰지 않는다. 모호하면 꼬리 질문 한 번.
5. 약했던 칸은 **조건을 바꾼 새 질문**으로 힌트 없이 한 번 더. "알겠다"만으로는 통과가 아니다.
6. 6문항이 끝나면 틀린 사실은 노트에 반영하고, 문서와 코드가 어긋나면 제출 전에 문서를 코드에 맞춘다. 시간이 부족하면 3문항만 하되 전제 틀린 문항을 하나 넣는다.

## 사용자가 할 것 (3시간 중 6번, 30초씩)
1. 분석 끝: "이게 뭘 만드는 과제야? 한 문장으로" → 따라 읽기
2. 방법 수준·A/B를 고를 때: 이유를 내 말로 붙여 보낸다
3. 단계마다: 이해 체크포인트 질문에 한 줄로 답한다
4. 검사·화면 확인: 결과 하나를 직접 눈으로 본다
5. 검사·문서 뒤: 코드 없이 무힌트 회상 네 문장 → `모의 확인 문제 해줘`
6. 제출 직전: `답 파일 보여 줘` → `Answers.md`를 두 번 읽고 「한눈에」·「핵심 결정 집중」의 핵심 단어만 기억한다. 질문 생성 대기 5~10분 동안 그것을 머릿속으로 다시 떠올린다.

이해가 안 되면 넘기지 말고 "이거 왜 이렇게 했어? 쉽게 두 줄로". 구조가 막히면 `역할별 데이터 흐름을 쉬운 말로 연습하자`, 판단 사례가 막히면 `내가 AI를 재검토시킨 사례만 질문해 줘`라고 친다.
