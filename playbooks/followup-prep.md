# 확인 문제 대비 — 작업하면서 미리 준비한다

## 알려진 형식 (공개 안내·10/31 응시자 후기 · 실제 화면이 우선)
- 제출을 확정하면 **질문 생성 대기 5~10분**이 있다(답변 시간 아님). 그다음 **약 6문항, 문항당 약 5분**이다.
- 문항마다 시간이 따로 흐르고 끝나면 자동 확정된다. 이전 문항으로 돌아갈 수 없고, 붙여넣기는 안 된다. 키트·AI도 쓸 수 없다.
- **질문은 AI가 내 제출물과 작업 기록을 읽고 사람마다 다르게 만든다.** 예: 검증용 스크립트에서 나온 질문, 에이전트가 쓴 문서에서 나온 질문, `AI_COLLABORATION.md`에 적은 Docker 문제를 짚은 질문.
- **답할 때 코드를 볼 수 없다.** 코드 조각을 해석시키는 형식이 아니다. 내가 만든 것을 기억으로 설명한다.
- 10/31에 나온 주제: 알고리즘 선택 이유, 모듈 책임과 데이터 흐름, 운영자/사용자 격리와 권한, 장애·동시 수정 시 동작, 모놀리스·동기/비동기·운영 전 고려, AI 코드 검증, 트레이드오프. → 9가지 카드로 정리했다: `playbooks/answer-cards.md`
- 공식 평가 축: **결과물 완성도 · AI를 이끈 방식 · 자기가 만든 것을 설명할 수 있는지**(기술·의도·인지). 서술형이 가장 큰 변별 요소였다는 후기가 많다.

## 핵심 전략 — 출제 범위를 내가 정한다
질문이 제출물에서 나오므로, **제출물을 내가 아는 것으로만** 채운다.
1. **제출 문서는 고정한다**: README가 요구한 것 + `DECISIONS.md` + `AI_COLLABORATION.md`(README가 다른 이름을 정하면 그 이름). 틀은 `templates/DECISIONS.md`, `templates/AI_COLLABORATION.md`. 각각 1~2쪽.
2. **AI가 따로 만든 잡문서·실험 파일·worktree·임시 스크립트를 제출물에 남기지 않는다.** 남길 검사 파일은 이름만 봐도 무엇을 확인하는지 알게 한다(`test_capacity_never_exceeded.py`).
3. **코드는 역할별 파일 4~6개**로 둔다. 파일 맨 위에 한국어 한 줄로 역할을 쓴다. 흐름 순서와 파일 순서를 맞춘다(`knowledge/service-architecture.md`).
4. **제출 전에 사람이 제출 문서를 전부 직접 읽는다.** 읽지 않은 문서는 내지 않는다.

## 작업 중 이해 체크포인트 (③ 단계마다 · 30초)
- 단계가 끝날 때마다 AI가 **"방금 만든 것 3줄 설명(파일 이름 포함) + 확인 질문 1개"**를 낸다.
- 사용자는 한 줄로 답한다. 틀리면 AI가 맞는 사실을 한 줄로 짚는다. 대화 기록도 채점되므로, 사람이 이해한 흔적이 남는다.
- 확인 질문은 카드 축에서 하나 고른다. 예: "이 데이터는 어디에 저장되고 누가 바꾸지?", "같은 요청이 두 번 오면?", "이 숫자는 어디서 다시 계산해 확인했지?"
- 사용자가 `넘어가`라고 하면 넘어간다. 강요하지 않는다.

## 확인문제 노트 — AI가 작업 중에 채운다
- **위치**: `<키트>/notes/확인문제-노트.md` (시험: `/tmp/kit/notes/…` — 제출 폴더 밖). 틀은 `templates/answer-notes.md`. 키트 폴더에 쓸 수 없으면 `/tmp/확인문제-노트.md`. **과제(제출) 폴더에는 만들지 않는다.** `/tmp`가 비면(환경 재시작) 키트를 다시 받고, 노트는 `DECISIONS.md`·`AI_COLLABORATION.md`·대화에서 확인되는 사실로 복구한다.
- **생성·복구**: 시작·이어하기·단계 전환 때 실제 파일이 있는지 본다(매 답마다 하지 않는다 — 토큰). 없으면 즉시 만든다. `DECISIONS.md`는 제출용 근거 기록이고 노트의 대체물이 아니다. 계획 승인·담당자 답·과거 검사를 새로 만들어 쓰지 않는다.
- **언제**: 단계가 끝날 때, 사용자가 A/B를 고르거나 AI 제안을 고치게 했을 때, 담당자 답이 규칙을 바꿨을 때, 기준선·개선 수치가 나왔을 때. 해당 카드 칸과 「외울 것」만 고친다.
- **얼마나**: 카드마다 최대 3줄, 파일 전체 70줄 이하. 덧붙이지 말고 바꿔 쓴다. **외울 문장만** 쓴다(노트 작업 자체·"미확인" 설명은 쓰지 않는다 — 미확인은 카드 7에만). 사례가 없는 카드는 비운다.
- **어떻게**: 실제 값과 출처 하나를 쓴다(`인사팀 20:52` · `내 가정` · `test 출력` · `README 7`). AI만 실행했으면 `(AI)`, 사람이 직접 봤으면 `(내가 봄)`. 사용자 확인이 기록돼 있을 때만 1인칭으로 쓴다.
- **사람 몫**: 「다시 한다면」·「시간 배분」은 사용자가 실제로 말한 것만 쓴다. 없으면 비우고, `노트 보여 줘` 끝에 "이 두 줄은 직접 생각해 두세요"라고만 덧붙인다.
- 파일을 쓰고 다시 읽어 존재·갱신·70줄 이하를 확인한 뒤에만 `노트 갱신: 카드 n`이라고 알린다. 쓰기에 실패하면 그 사실을 밝힌다.
- `노트 보여 줘`: 최신 상태를 확인·보완한 뒤 **파일 원문을 그대로 출력한다**(`cat`, 표·요약 금지 — 외울 문장이 원문이다).

## 모의 확인 문제 (⑥ — 마감 40~50분 전 · 15분 · 사용자가 `모의 확인 문제 해줘`)
1. AI는 **제출할 파일만** 읽는다(코드·제출 문서·검사 파일). 질문 6개를 카드 축에서 고르고, **그중 하나는 전제를 일부러 살짝 틀리게** 낸다. 실제 시험처럼 파일 이름이나 문서 속 사례를 짚는다.
2. **한 번에 한 문항씩** 낸다. 사용자는 1~3문장으로 답한다(코드를 보지 않고).
3. AI는 답을 **코드·출력과 대조해** 틀린 사실·빠진 단계(4단계 중 무엇)만 한 줄로 짚는다. 모범 답안을 길게 쓰지 않는다.
4. 6문항이 끝나면 틀린 사실은 노트 「모의 확인 문제 기록」에, 고친 사실은 해당 카드에 반영한다.
5. 답하기 어려웠던 부분이 **문서와 코드가 어긋난 곳**이면 제출 전에 문서를 코드에 맞게 고친다(코드가 기준).
6. 시간이 부족하면 3문항만 한다. 전제 틀린 문항 하나는 꼭 넣는다.

## 사용자가 할 것 (3시간 중 6번, 30초씩)
1. 분석 끝: "이게 뭘 만드는 과제야? 한 문장으로" → 따라 읽기
2. 방법 수준·A/B를 고를 때: 이유를 내 말로 붙여 보낸다
3. 단계마다: 이해 체크포인트 질문에 한 줄로 답한다
4. 검사·화면 확인: 결과 하나를 직접 눈으로 본다
5. 마감 40~50분 전: `모의 확인 문제 해줘`
6. 제출 직전: `노트 보여 줘` → 두 번 읽고 「외울 것」의 핵심 단어만 기억한다. 질문 생성 대기 5~10분 동안 「외울 것」을 머릿속으로 다시 떠올린다.

이해가 안 되면 넘기지 말고 "이거 왜 이렇게 했어? 쉽게 두 줄로" — 이해에도 도움이 되고 카드 6의 재료가 된다.
