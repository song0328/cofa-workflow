# 시험 화면에서 알아 둘 것 (웹 IDE 플랫폼)

공개 안내와 사전 점검에서 확인한 일반적인 화면 동작이다. 실제 화면·안내가 다르면 화면이 우선한다.

## 저장과 제출
- AI가 터미널에서 고친 파일은 바로 디스크에 써진다. **사람이 에디터에서 고친 파일은 Ctrl+S로 저장**한다. 저장되지 않은 수정은 보존이 보장되지 않는다.
- 에디터 탭·상단의 저장 표시(`저장됨` / `저장 안 됨`)를 본다. AI와 사람이 같은 파일을 동시에 고치면 저장 충돌이 날 수 있다 → 양쪽 내용을 보고 고른다.
- **`제출하고 문제풀기`를 누르면 작업 내용이 제출물로 고정**되고 확인 문제가 이어진다. 누르기 전에: 저장 안 된 파일 없음 · 제출 문서 작성 · **과제가 정한 검사 명령(README·package.json·처음 받은 test 파일 — `node test.cjs`든 `npm test`든 이름 무관)을 사람이 터미널에서 직접 실행해 통과 확인**(`playbooks/flow.md` 「제출 전 사람이 직접 돌리는 검사」) · 핵심 파일 직접 읽기.

## 화면 구성
- 위: 과제명 · 감독 연결 · CPU/RAM · 남은 시간 · 문제 신고 · 제출하고 문제풀기
- 왼쪽 아이콘: 파일 탐색기 · 검색 · 브라우저 미리보기 · **SaaS(네모 4개)** · MCP
- **SaaS 화면**: 과제에 배정된 업무용 서비스(업무 포털·사내 시스템·시트 등)가 가운데 영역에 열린다. 배정이 없으면 "할당된 SaaS가 없습니다"가 뜬다. **시작할 때 한 번 눌러 본다.** 내용이 있으면 README와 같은 과제 자료로 다룬다. 그 안의 승인·발송·결제 같은 실제 동작 버튼은 담당자 확인 없이 누르지 않는다(권한 밖 행동)
- 가운데: 에디터 + 터미널(`+`로 새 탭) / 오른쪽: 메신저(DMs) — 화면 도우미와 업무 담당자
- 단축키: 저장 Ctrl+S · 탐색기 접기 Ctrl+B · 내용 검색 Ctrl+Shift+F · 파일명 검색 Ctrl+P · 터미널 붙여넣기 Ctrl+Shift+V · 선택 없이 Ctrl+C = 실행 중단

## 알아 둘 동작
- 에디터의 HTML 미리보기(눈 아이콘)는 **그 파일 하나만** 보여 줄 수 있다. 다른 `.js`(데이터·로직)를 못 불러와 선택 칸·목록이 비어 보이면 코드 오류가 아니다 → 서버 + Browser 미리보기로 확인한다.
- **미리보기는 서버를 띄운 뒤에만** 열린다. 실제 포트·경로를 넣는다. 안 되면 원격 데스크톱의 브라우저가 대안일 수 있다.
- **메신저 답을 기다리는 동안에도 작업 공간을 쓸 수 있다.** 담당자 답을 기다리며 AI 작업을 병렬로 진행한다.
- 과제 폴더에 `README.md`와 `README.en.md`처럼 **언어별 README가 함께** 있을 수 있다. 둘 다 훑고, 내용이 다르면 함정으로 기록한다.
- 홈 폴더에 숨김 파일·`uploads/` 같은 환경 파일이 섞여 있다. 과제 파일만 다룬다.
- **브라우저 권한 창(예: 클립보드)이 뜨면 전체화면 이탈로 기록될 수 있다.** 침착하게 바로 처리하고 전체화면으로 돌아간다.
- 전체화면 유지, 다른 창·탭 이동 금지. 플랫폼 오류는 `문제 신고`로 시각·증상 접수.

## 10/31 본시험에서 확인된 것 (응시자 기록 · 회차마다 다를 수 있다)
- **작업 폴더가 홈(`~`)이고 홈이 git 저장소다.** `./kit`은 왼쪽에서 읽기 위해 잠시 두지만 제출물에는 넣지 않는다. 제출 직전 카드가 제출물을 대조한 뒤 사람이 `mv -- ./kit /tmp/kit`으로 옮긴다. 실험 파일·worktree는 만들지 않고 `git add .`도 금지한다.
- **자동으로 함께 넘어가는 것**: AI 대화, 터미널 세션, AI 도구 설정, **git 로그와 diff**, 테스트 실행 결과, 결과물 파일. 커밋 메시지·검사 결과도 평가 자료다.
- 실행 환경: `python3`만 있음(`python` 없음) · Node 22 · `npm i -g` 막힘 · pip 가능 여부는 회차마다 확인 · 외부 접속은 승인이 필요할 수 있음. 서버는 `0.0.0.0`, 포트는 1024 이상(관리용 8090·8081·2222는 피한다).
- GUI 파일 탐색기가 느리거나 멈출 수 있다(삭제 안 됨·"업로드 중"). 파일 조작은 터미널에서 한다.
- **Chrome 비밀번호 저장·자동완성 팝업이 전체화면을 풀어 경고가 남는다.** 시험 전에 Chrome 설정에서 꺼 둔다. 로그인 화면을 시험할 때 특히 주의한다.
- 신분증은 안내 없이 중간에 비추라고 할 수 있다. 곁에 둔다.
- 운영 공지(시간 연장 등)가 **메일이나 문의 답변으로만** 오기도 했다. `문제 신고`·문의 창으로 물으면 개별 답이 온다. 화면 새로고침이 필요하다는 공지도 있었다.
- 제출 뒤 확인 문제 화면이 안 뜨면 바로 나가지 말고 새로고침한다.
- 연결이 끊겨도 원격 Codex는 계속 돌았다. `playbooks/codex.md` 「끊김·재접속」.

## 재시험 회차 (운영 안내·본인 메일이 우선)
- 회차 시간 같은 당일 사실은 본인 메일과 실제 화면에서 확인한다. 키트에는 특정 회차의 절대 시각을 사양처럼 고정하지 않는다.
- 시작 시 화면의 남은 시간을 AGENTS.md 7칸에 적는다. **60분 남으면 기능 동결, 45분 남으면 검사·문서, 15분 남으면 제출 시작**한다. 실제 화면 안내가 다르면 화면이 우선이다.
- 제출 순서: `제출하고 문제풀기`(미리보기 — 일부 파일만 보이고 숨김 폴더가 빠질 수 있다) → `제출물 확정하고 문제풀기` → 질문 생성 대기 5~10분(답변 시간 아님) → 6문항 → `답안 제출하고 마치기` → 제출 ID·파일 수 확인.

## 확인 문제(제출 후)
- 문제마다 시간이 따로 시작되고, **시간이 끝나면 쓰던 답이 자동 확정**된다. 빈칸으로 두지 않는다.
- 이전 문제로 돌아갈 수 없고, 복사·붙여넣기를 쓸 수 없다. 키트·AI도 쓰지 않는다.
- 출제 AI는 제출 폴더의 파일을 전부 읽고, 한 주제에 몰려 비슷한 질문을 반복하기도 한다(다른 Cofa 시험 후기).
- 대비는 `playbooks/followup-prep.md`, 읽을 파일은 제출 루트 `Answers.md`.
