# 검증 — "완료"는 실행 결과로만 말한다

## 원칙
- AI의 "통과했습니다"를 믿지 않는다. **검사 명령의 실제 출력과 종료 코드**를 본다. (AI는 통과라 했는데 파일 앞 BOM 하나 때문에 실제 검사가 실패한 사례가 있다.)
- 기대값은 구현 코드와 **독립적으로** 정한다(README·담당자 답에서). 같은 함수를 두 번 불러 비교하지 않는다.
- 요건마다 **정상 · 경계 · 오류** 입력을 하나씩 고른다.
- **숫자 결과는 다른 경로로 검산한다.** 예: 합계를 행 단위로 한 번, 그룹 합으로 한 번 / 일수를 달력으로 한 번, 날짜 차이로 한 번. 두 값이 다르면 어느 쪽이 맞는지 이유를 적는다.
- 규칙이 결과를 바꾸는지 보인다: "중복을 안 지웠다면 / 정정을 안 반영했다면 값이 어떻게 달라지나" 한 줄 — 규칙을 지킨 근거가 된다.
- 상대 주장·초안(다른 AI 초안, 팀 의견)은 조항·사실만으로 받아들일지 판정하고, 받아들이면 값이 어떻게 바뀌는지 계산한다.
- **제공된 검사와 AI가 만든 검사를 나눠 보고한다.** AI가 만든 검사가 통과한 것은 "코드가 AI의 해석대로 돈다"는 뜻일 뿐이다. 보고할 때 사례 하나를 `입력 → 기대값(출처: README n줄/담당자 답) → 실제`로 보인다.
- **HTTP 200 ≠ 화면 정상.** 서버 응답과 실제 화면(버튼·입력·빈 상태)을 각각 확인한다. 200인데 흰 화면이었던 사례가 있다.
- 실패하면 실패 문구를 **그대로** AI에게 주고 "원인 찾아서 고쳐". 사람이 직접 돌린 검사가 검증 근거로 남는다.

## 화면 연결 검사 (브라우저 없이)

### ui_sim 짧은 요청 처리
사용자가 `ui_sim 해줘`·`ui_sim으로 확인해`라고만 해도 AI가 아래를 수행한다. 사용자가 경로·명령을 외우거나 도구를 연결할 필요는 없다.

1. ui_sim은 MCP나 등록된 도구가 아니라 **키트 안의 로컬 Node 파일**이다. `AGENTS.md`의 키트 경로를 먼저 보고, 없으면 과제의 `kit/tools/ui_sim.cjs`, `/tmp/kit/tools/ui_sim.cjs` 순서로 실제 파일을 확인한다. 둘 다 없으면 현재 접근 가능한 키트 위치를 찾는다(홈 전체·비밀 설정은 검색하지 않는다).
2. README의 실행 화면 HTML을 찾아 `node <찾은 키트>/tools/ui_sim.cjs <HTML> --list`를 실행한다. 찾은 키트 경로와 명령을 과제 `AGENTS.md`에 적어 다음 요청에도 유지한다.
3. 출력에 나온 id를 사용해 정상·경계·오류 흐름을 직접 실행한다. README·담당자 답의 기대값과 실제 출력을 대조해 짧게 보고한다. 기존 `test.cjs` 통과만으로 ui_sim을 실행했다고 말하지 않는다.
4. 명령 자체가 액세스 거부로 시작되지 않으면 **스크립트 부재와 구분**한다. Windows에서 PowerShell 실행만 막혔고 허용된 cmd 실행이 이미 가능하다면 그 방식으로 같은 명령을 실행한다. 명시된 권한·정책 거부는 우회하지 않는다. 계속 실행할 수 없으면 실제 오류와 사람이 터미널에서 실행할 명령 한 줄만 준다. "ui_sim 환경 연결"·"도구 설치"를 요구하지 않는다.
5. 실제 파일이 없을 때만 키트를 다시 받도록 안내한다. 스크립트 실행 후 화면 기능이 지원되지 않으면 한계를 밝히고 Browser 확인 1~3개로 넘긴다. 진짜 브라우저 자동 조작이나 ui_sim 개조로 시간을 쓰지 않는다.

ui_sim은 확인용으로만 실행한다. 과제 코드·검사 파일에 키트 참조를 넣지 않는다. CSS·배치·fetch는 검증했다고 말하지 않는다.

```bash
node <키트>/tools/ui_sim.cjs index.html --list
node <키트>/tools/ui_sim.cjs index.html "set employee=E1" "set start=2026-11-07" "click submit" "read message list"
```
- 터미널에서 확인용으로만 돌린다. **과제의 `test` 파일에 넣지 않는다**(제출 시 키트가 없어 깨진다).
- 스크립트 로드 오류·선택지 없음·클릭 후 표시를 확인한다. 종료 코드 1이면 오류가 있다. 레이아웃·CSS·서버 요청은 확인하지 못한다.

## 사람이 직접 할 것
1. README에 적힌 검사 명령을 터미널에서 직접 실행
2. 화면이 있으면 정상·경계·오류 입력 3개를 직접 넣어 보기 (AI에게 입력과 기대 결과만 받는다)
3. 제출 전 AI가 만든 핵심 파일을 직접 읽기
