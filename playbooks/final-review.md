# 다 됐을 때 — 남는 시간 재점검

요건을 다 마쳤는데 시간이 남을 때 한 번 더 본다. 목적은 **기능을 늘리는 것이 아니라 점수를 잃는 곳을 찾는 것**이다: 놓친 요건, 숨은 조건, "됐다고 했지만 실제로는 안 된 것", 설명 못 하는 결과.
짧은 요청: `다시 점검해 줘` → 이 파일. AI는 먼저 남은 시간으로 판을 고르고, **찾기와 고치기를 나눈다**(찾는 동안 코드를 고치지 않는다).

## 0. 남은 시간으로 판을 고른다 (과제 타이머 기준)
| 남은 시간 | 판 | 고칠 수 있는 것 |
|---|---|---|
| 60분보다 많음(동결 전) | **전체 점검** 1~5 | 필수 요건·숨은 조건 반영, 작은 개선(아래 4의 기준을 넘을 때만) |
| 60~20분(동결 뒤 · ⑥ 끝남) | **동결 점검** 1·2·3 | 필수 경로 버그 + 회귀 테스트, 문서를 코드에 맞추기, 검사 추가. 새 기능 금지 |
| 20분 이하 | 하지 않는다 | → `stages/7-submit.md` |
- 고치기 전에, 기존 Git 저장소면 지금 상태를 커밋해 둔다(되돌릴 곳). 아니면 바꿀 파일만 `/tmp`에 복사.

## 1. 진짜 다 됐나 (증거로 닫기)
- 요건표 R마다 `완료`의 증거가 있나: 검사 이름·출력 / 사람이 본 화면 번호(`S2-1`). **AI가 실행만 한 것은 `(AI)`, 사람이 직접 본 것만 `(내가 봄)`.** 증거가 없으면 `미검증`으로 되돌린다.
- 깨끗한 상태로 처음부터: 새 데이터 폴더로 서버를 다시 띄우고 README의 실행·검사 명령을 **README에 적힌 그대로** 한 번 친다(설명서대로 안 되면 채점자도 못 돌린다).
- 역할마다(이용자·운영자 등) 핵심 흐름 하나를 사람이 직접 눌러 본다: 정상 1 · 경계 1 · 오류 1.

## 2. 놓친 것 (원문을 다시, 내 사양을 보지 않고)
- 작업 중 만든 요약·요건표가 아니라 **README 원문을 문장 단위로** 다시 읽고 요건표와 대조한다. 특히 `단, 다만, 제외, 이상/초과/미만, 반드시, 각각, 모든, 동시에`, 숫자, 예시 출력의 형식(열 이름·순서·소수점·정렬).
- 제공 자료의 **모든 파일·모든 열이 쓰였나.** 안 쓴 것은 이유가 있나(쓰지 않은 열이 숨은 조건인 경우가 많다).
- 담당자 DM을 처음부터 다시: 받은 말이 전부 「2-1」에 있고 **각각 검사가 있나**. 지나가듯 한 말·덧붙인 조건도.
- README가 가리킨 SaaS 화면·공지를 한 번 더 열어 본다(시행일·변경 공지).
- 제출물 목록(AGENTS.md 「8」)과 README 제출 안내가 같은가: 파일 이름·위치·형식.

## 3. 숨은 조건 (한 번 더)
- `python3 <키트>/tools/data_profile.py <자료 폴더>`를 다시 보고, 처리하지 않은 예외 후보가 남았나(`playbooks/edge-hunt.md` "사람 눈으로 볼 9가지").
- 「3. 가정」 중 **모든 결과에 영향이 큰 것** 하나를 담당자에게 근거와 함께 다시 묻는다. 아직 말 걸지 않은 담당자가 있으면 그 사람 관점의 질문 하나(`playbooks/stakeholder.md`).
- **금지만 묻고 선호는 안 물었나**: 받은 제한 규칙마다 "그 사람들이 대신 가장 원하는 것"을 물었는지 본다. 안 물었으면 하나 묻고, 답이 품질 지표(휴무·이동·희망 등)를 바꾸면 배정에 반영한다.
- 함정 입력으로 깨 보기: 경계값(정확히 기준값), 빈 입력, 중복, 자정 넘김, 권한 밖 요청. 결과가 규칙대로가 아니면 버그로 기록.

## 4. 더 좋은 방향 (바꿀지 말지 고르기)
AI는 개선 후보를 **표로만** 낸다. 고르는 것은 사람이다.
| 후보 | 근거(README·담당자·측정값) | 얻는 것 | 위험 | 걸리는 시간 | 설명할 수 있나 |
- **바꾸는 기준(모두 만족)**: 요구·담당자 말에 직접 닿는다 · 30분 안에 끝난다 · 검사로 좋아진 것을 증명할 수 있다 · 서술형에서 내 말로 설명할 수 있다.
- 기준을 못 넘는 후보는 **만들지 않고** 제출 문서의 "운영 전에 할 것 / 트레이드오프"에 한 줄로 남긴다 — 이것도 서술형 재료다(`playbooks/scope.md`).
- 고른 것은 MY.md에 `결정`으로 이유와 함께 적는다.

## 5. 고치기와 마무리
- 발견마다: `발견 · 근거(파일:줄·DM 시각) · 영향 · 제안 · 시간` 한 줄 표 → 사람이 번호로 고른다 → **한 번에 하나**, 고친 뒤 전체 검사 다시.
- 아무것도 못 찾았으면 "점검 항목 n개 확인, 발견 없음"이라고만 쓴다. 찾은 척하지 않는다.
- 결과를 바꾼 것은 제출 문서 결정 기록에, 고치지 않은 발견은 "알려진 한계"에. 그다음 ⑥(아직이면) 또는 ⑦.
- 원하면 계약이 확정된 지금이 **읽기 전용 검증 탭**을 쓰기 좋은 때다: 2·3을 다른 탭에 맡기고 메인은 1을 한다(`playbooks/parallel.md`).
