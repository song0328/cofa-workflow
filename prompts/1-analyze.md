# ① 분석 — 코드 수정 없이 과제를 이해한다

사용자가 이 단계를 시키면 아래를 따른다. **사용자가 다음 단계를 지시하기 전까지 계속 코드·파일 수정 금지.**

1. 먼저 현재 경로, 과제 README 위치, git 상태만 확인한다. 체험·안내용 README와 실제 과제 README를 구분한다.
2. README부터 읽고 제공 파일을 훑는다. 다음 여섯 가지로 정리한다.
   - **목적** — 누가 무엇을 위해 쓰는가 (한두 문장)
   - **입출력** — 입력 형식, 출력 형식, 제출 파일 이름과 위치
   - **요건표** — 필수·선택을 나눠 번호를 매기고, 각 요건의 근거 파일·줄
   - **함정** — 파일끼리 충돌, 팀 의견 vs 확정 정책, 예외 데이터(중복·정정·취소), 경계값, 오류 우선순위, 권한 밖 행동(실제 발송·결제·승인). 자세히는 `playbooks/traps.md`
   - **담당자 질문** — 파일에 답이 없는 업무 규칙만, 8개 이내 (`playbooks/stakeholder.md` 규칙)
   - **가정** — 질문하지 않고 내가 정할 것과 그 영향
3. 출력은 표 위주로 짧게. 구현 계획·코드 제안은 아직 하지 않는다.

질문 작성 규칙(요약): 한 질문에 한 가지 · 작은 것부터(목적·사용자 질문은 맨 끝 1개) · 예/아니오·숫자·정확한 값 하나로 답할 수 있게 · 따옴표로 묶어 그대로 보낼 수 있게 · 파일에 답 있는 건 묻지 않는다.

---
사용자가 칠 짧은 문장 예: `KIT-INDEX를 보고 prompts/1-analyze.md대로 분석만 해. 과제는 <경로>.`
