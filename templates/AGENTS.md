# AGENTS.md — 이 과제의 작업 규칙 (Codex가 매 요청 자동으로 읽는다 — 명령으로 다시 열지 않는다)

## 0. 진행자 규칙 (⓪ 시작에서 이 칸부터 만든다)
- 진행: ⓪시작 · 시작 --:-- · 다음: (한 줄)  ← 단계가 바뀔 때마다 고친다
- 키트: /tmp/kit (`playbooks/flow.md` 진행자 모드). 매 답 끝에 `── 다음 ──` 칸(단계 · 사람이 할 일 · 나에게 보낼 말 예 · 확인해 볼 것)
- 담당자 질문은 경우 하나에 질문 하나. 사람은 첫 번째만 보낸다
- README·자료에 업무 기준이 없으면 사람에게 묻지 말고 담당자에게 보낼 질문 한 문장(받는 사람 포함)을 바로 준다
- 담당자가 "기준 없음"이라 답한 것·설계 선택만 A/B로 멈추고 사람이 이유와 함께 고른다
- 사람이 계획을 확인하기 전에는 코드를 고치지 않는다
- 사람이 붙여 넣은 SaaS·공지·담당자 답은 **받는 즉시** 아래 「2-1. 받은 자료」에 출처·시각과 핵심 문장 그대로 적는다(대화가 압축·끊겨도 남게). 이미 적힌 자료를 다시 달라고 하지 않는다
- 담당자가 "기준 없음"이라 한 주제는 「3. 가정」에 `기준 없음(담당자 시각)`으로 적고 **같은 주제를 다시 묻지 않는다**
- README가 최신 기준이 있다고 가리킨 SaaS·공지는 **가정이 아니라 자료**다. 담당자가 그 항목에 "기준 없음"이거나 공지를 따르라고 하면 최신 공지를 확정 사양으로 쓰고, 담당자 답과 다른 점은 결정 문서에 채택 근거와 함께 남긴다(사람에게 A/B를 묻지 않는다)
- 제출 전에는 `노트 보여 줘`를 먼저 권하고, 과제가 정한 검사 명령(이름 무관)을 찾아 사람이 터미널에서 직접 돌리게 한다. 통과 출력을 사람이 보기 전에는 제출을 권하지 않는다
- "통과"는 제공 검사 / AI가 만든 검사를 나눠 말하고, 출처 붙은 사례 하나를 보인다
- 결정·가정은 과제가 요구하는 결정 문서가 있으면 거기에 적는다
- 단계가 끝날 때마다 키트 `notes/확인문제-노트.md`의 해당 칸만 고친다(Q마다 3줄, 60줄 이하, 실제 있었던 일만, 제출 폴더 밖)
- 토큰도 채점된다: 질문 문장 만들기·A/B 받기·짧은 설명에는 명령을 실행하지 않는다. 파일은 필요한 부분만 읽는다
- 단계 전환·`이어서`·`노트 보여 줘` 때 위 노트의 실제 파일 존재를 확인한다(명령은 묶어서 1~2회). 없으면 키트의 `templates/answer-notes.md`로 만들고 현재 기록에서 확인되는 사실만 복구한다. DECISIONS.md만으로 대신하지 않는다. 담당자 답·사용자 결정·검사 결과가 바뀌면 관련 Q와 A·B·C를 갱신하고 `노트 갱신: Q번호`를 알린다. 사용자 직접 확인과 AI 실행을 구분하고 모르는 사실은 미확인으로 둔다.
- `확인문제 대비해 줘`·`노트 정리해 줘`·`노트 보여 줘`는 위 노트 생성·갱신 후 표시하는 요청이다. 단계·요건 상태도 실제 기록에 맞게 고치며, 계획 확인 없이 다음 구현으로 넘어가지 않는다.
- 키트 파일은 확인용으로만 실행한다. 과제 파일이 키트를 읽거나 복사하지 않는다(키트 없이 검사가 돌아야 한다)
- `ui_sim 해줘`만 받아도 직접 실행한다. ui_sim은 연결 도구가 아니라 `<키트 실제 경로>/tools/ui_sim.cjs` 파일이다. 먼저 실제 경로를 확인해 이 줄과 아래 명령을 채운다: `node <키트 실제 경로>/tools/ui_sim.cjs <화면 HTML> --list`. 그 id로 정상·경계·오류를 확인한다. 연결·설치를 요구하거나 파일 확인 전에 없다고 말하지 않는다. 실패하면 `playbooks/verification.md`의 「ui_sim 짧은 요청 처리」를 따른다.

## 4. 금지
- README·담당자 답에 없는 기능·필드·오류 코드를 만들지 않는다
- README·원자료·플랫폼 설정을 수정하지 않는다
- 실제 브라우저 조작·겉모양 확인은 사용자가 한다. AI는 로컬 ui_sim으로 입력·클릭·표시를 검사한다(브라우저를 몰래 띄우지 않는다).
- 실제 발송·결제·승인·외부 공개 같은 동작을 하지 않는다
- 필수조건이 끝나기 전에 선택조건을 시작하지 않는다

## 5. 규칙
- 완료라고 말하기 전에 검사 명령을 실행하고 출력·종료 코드로 증명한다
- 업무 기준이 없으면 멈추고 담당자 질문 한 문장을 따옴표로 낸다
- 한 번에 한 단계만. 끝나면 바뀐 파일·검사 결과·요건표 갱신
- 검사 통과한 단계마다 **과제 파일만** 커밋한다 (`git add <파일>`; 홈 전체 `git add .` 금지)
- 실행 명령은 `python3` (`python` 없을 수 있음), 서버는 `0.0.0.0:<포트>`
