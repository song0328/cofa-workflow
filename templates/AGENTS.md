# AGENTS.md — 작업 규칙 (매 요청 자동으로 읽힌다 · 짧게 · cat으로 다시 열지 않는다)

## 0. 상시 규칙
- 진행: ⓪시작 · 시작 --:-- · 종료 --:-- · 제출 시작 --:-- · 다음: (한 줄)  ← 단계마다 고친다
- 키트 `/tmp/kit`: **지금 단계 카드 `stages/<n>-*.md` 하나만**. 더 필요하면 `python3 /tmp/kit/tools/kit_read.py <파일> "<절>"`로 절만. 통째 읽기 금지
- 매 답 끝 `── 다음 ──`: 단계 · 사람이 할 일(복사할 문장·받는 사람) · 나에게 보낼 말 예 · 확인해 볼 것
- 답은 한국어, 새 파일·폴더 이름은 영어 소문자. 「나에게 보낼 말」은 개발자 지시 한 문장(무엇+왜+확인 기준) **300자 이내**(입력 1000자 제한 — 긴 자료는 나눠서·파일 경로로, `playbooks/codex.md`). 결정은 선택지·트레이드오프·추천 → 사람이 이유를 붙여 고른다(`playbooks/lead-like-dev.md`)
- 탭 여러 개: AGENTS.md·DECISIONS.md·AI_COLLABORATION.md·노트 수정과 커밋은 메인 탭만. `/tmp/kit/work/T*.md` 카드를 받은 탭은 보조 탭 — 카드 규칙이 이 규칙보다 우선(`playbooks/parallel.md`)
- 업무 기준이 없으면 추측 구현 금지 → 담당자 질문 한 문장(물음표 하나, 근거 포함). "기준 없음"이면 「3. 가정」에 적고 다시 묻지 않는다. 설계 선택만 A/B로 사람이 이유와 함께 고른다
- 받은 답·공지·SaaS 내용은 즉시 「2-1」에 원문·출처·시각(README가 가리킨 공지는 자료)
- 사람이 계획을 확인하기 전 코드 수정 금지. 한 번에 한 단계, 검사 출력으로 증명(제공 검사 / AI 검사 구분). 과제 파일만 커밋(`git add <파일>`, 메시지에 R번호)
- 제출물 = README 요구 문서 + `DECISIONS.md` + `AI_COLLABORATION.md` + 역할별 코드 4~6개(첫 줄에 한국어 역할 주석). AI 제안을 받아들이거나 고치거나 버리면 즉시 `AI_COLLABORATION.md`에 한 행. 잡파일·worktree·키트를 과제 폴더에 두지 않는다
- 단계 끝: 이해 체크포인트(3줄 + 확인 질문 1) · `/tmp/kit/notes/확인문제-노트.md`의 해당 카드만 갱신(실제 일만)
- 토큰: 질문 문장·A/B·짧은 설명에는 명령 0회. 파일은 필요한 부분만(`grep -n`, `sed -n`, kit_read)
- 짧은 요청: `이어서` → 진행 줄의 단계 카드 · `노트 보여 줘` → 노트 원문 `cat` · `모의 확인 문제 해줘` → `stages/6-prepare.md` · `ui_sim 해줘` → verification.md "ui_sim 짧은 요청 처리" · `막혔어` → `playbooks/recover.md` · `T2 끝났어` → 결과 파일 검증 후 반영

## 4. 금지
- README·담당자 답에 없는 기능·필드·오류 코드를 만들지 않는다
- README·원자료·플랫폼 설정을 수정하지 않는다
- 실제 브라우저 조작·겉모양 확인은 사용자가 한다. AI는 로컬 ui_sim으로 입력·클릭·표시를 검사한다(브라우저를 몰래 띄우지 않는다).
- 실제 발송·결제·승인·외부 공개 같은 동작을 하지 않는다
- 필수조건이 끝나기 전에 선택조건을 시작하지 않는다

## 5. 규칙
- 완료라고 말하기 전에 검사 명령을 실행하고 출력·종료 코드로 증명한다
- 업무 기준이 없으면 멈추고 담당자 질문 한 문장을 따옴표로 낸다
- 한 번에 한 단계만. 끝나면 바뀐 파일·검사 결과·요건표 갱신
- 검사 통과한 단계마다 **과제 파일만** 커밋한다 (`git add <파일>`; 홈 전체 `git add .` 금지)
- 실행 명령은 `python3` (`python` 없을 수 있음), 서버는 `0.0.0.0:<포트>`
